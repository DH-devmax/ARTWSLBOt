# 群管底座与人工操作边界

日期：2026-11-03，时间为Asia/Shanghai。

## 当前归属

`internal/features`统一返回`native_usage`，其归属独立于协议支持、
接入状态、产品排除项和历史受控证据。能力ID、旧授权和历史审计不删除。

| 归属 | 内容 | 使用方 |
| --- | --- | --- |
| `foundation` | 群消息接收、必要群资料、名单、角色、群管、文本与媒体发送等 | 通过各自准入后的群管助手或业务模块 |
| `manual` | 注册、登录、账号设置、人工好友审批、语音播放、文件下载及对应子项 | 现有人工入口；未实现内容仍只读 |
| `excluded` | 文件发送 | 沿用不接入决定，保留历史ID |

本次用户明确列出的十二项均移出底座表，放到超管的“账号与人工操作”页签；
账号昵称、头像及其他账号设置也随账号设置父组归类，避免共享号池的全局资料
混入单群助手。会话恢复属于接入运行所需能力，仍计入底座。
人工页签不展示业务依赖和底座进度，不新开注册、短信、登录或原生动作。

后端`NativeBusinessAllowed`供业务依赖和助手能力目录共同使用。
人工能力即使以后有完整原生验收，也不因该状态而取得自动调用资格。
好友自动审批退出当前业务目录；旧`friend_approval`仍可识别但无可编辑字段，
不能通过旧配置接口开启。现有逐项人工审批不变。

旺商聊底座为35个父能力、39个独立验收项，26个父能力有指定场景历史记录，
对应29个独立项。原27条历史记录仍全部保留，其中账号资料记录移入人工区，
不是验收倒退。辣椒聊独立维护，不继承旺商聊证据。

均为双方留存副本计数，不是独立用户发送次数。

认证应用消息中有两条@投影，没有引用301字段，也没有29–38原生引用路由。
这次检查了原始留存包的字段形状，不再仅依据旧清单或页面投影判断；
没有把转发、普通文本或其他群样本冒充引用。已有图片、转发、名片、视频、
头像和撤回读取证据继续有效，不重复生成测试消息或批量操作。
