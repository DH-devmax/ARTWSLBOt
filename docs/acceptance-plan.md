## 6. P2：授予/撤销管理员与权限变化

R3/R4在P0放行后按下面固定顺序进行；所有角色修改仅针对B。

| 阶段 | A/B预期角色 | 验证 |
| --- | --- | --- |
| 初始 | A owner；B恢复到已记录原值，测试普通成员场景需member | B无管理权限，A不能被目标选择器列为可处分目标；本地/合成核对拒绝 |
| 授权 | A owner；B admin | A或所有者官方客户端单次授予；双方完整成员证明一致，旧member快照失效 |
| 有权操作 | A owner；B admin | B全群禁言/解除各一次并回读；不处分群主；网站显式权限、套餐和群授权仍需满足 |
| 撤权 | A owner；B member | 单次撤销；旧页面/旧缓存/旧epoch不能继续提交，排队意图和迟到结果按当前角色处理 |
| 恢复 | 原始角色、群禁言和服务设置全部恢复 | 双侧角色和群设置读回一致；原始为admin时需预留恢复授权及次数，不遗漏第三次修改 |

R3“2次”以原始为member的升再降为基准。原始为admin又需走完整升降序列时，
必须在执行前把新增恢复动作明确列入计划与授权；不得执行中自动补次数。
撤权后真实拒绝用例只检查一项受控管理动作；其他越权、群主/管理员互相处分、
跨租户、旧会话、错误平台/目标/租约/过期窗口等组合由合成矩阵覆盖。
“撤权正确拒绝”与“平台已实现授撤管理员”分别出具结论。

## 8. P4：Web助手、热群与商用隔离

1. Web群管助手：已授权群按钮、唯一空会话、首问标题、最多十轮、切群迟到隔离、
   查询→建议→本人明确确认→CAS保存→运行规则读回。保存后实际业务生效另需P3通过。
2. 真实生成：补全并人工核验普通输入/输出/缓存读写费率、可信usage、供应商留存政策；
   已确认USD=USDT记账不补出缺失报价。单次测试明确积分上限和月预算，
   无自动付费重试，未知保留预留。无明确金额授权时只做合成验证。
3. 热群：与Web助手分开；当前maibot面板未认证，先由所有者准备同平台独立chat身份。
   测试原生事件→heatbot→共享网关→文本建议→最终控制→测试群对端接收；
   在群/角色/套餐/绑定/人设/路由版本变更与取消后不得发送迟到文本。
4. 两租户：在隔离部署构造授权/未授权账号群、owner/manager/operator/viewer、
   成员allow/deny、套餐过期/降级、撤权立即失效、查询/SSE/附件/会话/预算隔离。
   接收连接所有者与网站切换无关；网站角色不继承原生管理身份。
5. 商业账期：隔离库验证720小时、提前续费、不提前发积分、不结转、usage未知冻结、
   对账/冲正只追加、幂等与重启恢复。真实USDT收款或真实商业订单本轮不自动执行。
6. 超管仅验助手安全审计和人工管理；独立超管聊天已退场，不列核心缺口。
   辣椒聊Web助手尚未适配，不能把WSL助手复制作用域后直接开放。
7. 可选扩展（学习、人物印象、表达、长期/媒体记忆、受审工具）单独排期；
   默认关闭应不排队、不检索、不建索引、不调用模型，关闭/取消/恢复与跨群隔离用合成证明。
   其独立调度未实现，不把配置意向当运行能力，也不接到解码/ACK同步路径。

## 10. 最终交付与完成条件

- 每个平台分别出具能力清单、运行版本、每用例的真实/合成证据、失败原因及未支持项。
  待前置项必须修复并重测，不能通过改目录状态或隐藏按钮使计数变好。

  `internal/features/acceptance.go`仅记录经过审核的真实子场景，不承载凭据或正文。
- 受控通过、生产能力准入、native_ready、ai_ready分别审核。
  只有对应完整格式、权限、业务和故障门槛均通过的能力才更新production accepted。
  账号/平台/业务不完整时继续关闭其执行入口；全局readiness不因单平台单次成功而打开。
- 每批收尾只读确认：A/B均在原群并恢复原角色、昵称/隐私/群政策与业务配置恢复、

  测试公告和财务/操作审计按保留契约留存，不为“清理”删除证据。
- 执行顺序：P0按依赖补齐 → P1接收/发送/撤回 → P2角色变化与群管 →

  合格自有好友申请样本、独立chat身份，以及明确金额的付费/真实商业验证。
  已可从账号/目录核实的群号、身份和重复授权不再索取。
