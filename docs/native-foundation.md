核对日期：2026-10-29，Asia/Shanghai。依据当前产品工作树；各批次的候选与实际部署

## 本轮补齐

- `internal/nativeauth/members.go`：固定 `/v1/group/get-group-members` 读取，
  参数为业务群 ID、`v="0"` 和明确的后续游标。沿用现有桌面签名、加密、
  请求序号和响应错误处理，不运行完整桌面客户端。
- 参考本地已审阅的 AstrBot `a672ef9` 目录副本
  `directory.py::member_directory` 的分页/去重结构；仅识别明确的
  `GROUP_ROLE_OWNER/ADMIN/MEMBER`。其他字符串保持未知，类型错误和互相冲突的
  角色拒绝，不套用其他协议的数字角色或猜测 `type` 字段含义。
- 账号内串行，复用全局 2 个读取在途及每账号 16 个排队上限。成员读取总期限仍受
  15 秒读取/接口期限约束，最多 100 页、10000 人和约 4 MiB 安全投影预算。
  每页继续受现有原生 HTTP 响应/解压限制；到达上限不返回“完整”名单。
- 拒绝游标循环、宣称有下一页但缺游标、游标歧义、身份交叉映射、跨页记录变化、
  错误群 ID 及取消。失败不交付部分结果、不自动重试。无传输身份的成员可只读展示，
  `mapping_complete=false`；不能用于发送、@ 或群管执行。
- `internal/gateway/members.go`：仅允许当前账号新鲜目录中的群，账号 epoch、
  部署版本、加密会话在返回前再次核对。复用持久 429 冷却，不修改会话、
  接收开关、`account_groups` 或租户群授权。
  账号自身角色还需成员传输身份匹配当前登录会话；缺失则未知，冲突拒绝。
- `ReadScheduler.Value` 为同一个待执行资源的合并请求共享不可变结果。
  原 `Do` 保持兼容；不同账号/群、会话 epoch 或部署版本不会混用结果。
  正在执行的任务仍不复用，避免复用已失效的会话。
- 新增超管 POST `/api/v1/accounts/{id}/native-members`，只接受 `group_id`。
  沿用 Cookie、CSRF、工作台检查；等待结束后重新核对网站会话、禁用状态、
  超管角色及账号作用域。租户不能读取共享账号完整成员名单。
- 消息中心 → 原生群组 → 查看成员，按当前账号/群打开只读弹窗，支持本地搜索、
  50 人分页、角色和缺失映射状态。关闭、切换账号或卸载会取消请求并清除名单，
  不写浏览器持久存储、不记录原始响应、不在后台轮询所有群。

这里的 `complete=true` 仅表示支持的分页契约已正常终止，不证明上游返回了
真实全员，也不是原生权限许可。真实分页完整性及角色语义仍需隔离账号验收。
读取出的管理员角色不自动写入可信权限表，也不开放管理动作。

## 下一批底座实施顺序

1. **原生文本发送与回执**：先建立合成编码/签名向量，再补 IM 出站匹配和可靠操作记录；
   受控测试与生产执行开关分离，未获得隔离范围授权不发真实消息。
2. **提交时统一控制栅栏**：校验用户、租户、套餐、群归属、原生身份、账号/绑定 epoch、
   当前角色、目标保护、期限及测试次数。排队后失效必须在真正提交前阻断。
3. **引用与 @**：只能引用本群已认证消息、使用已核验成员身份和同群发送路由；
   输出构建复用第一步，不另建平行发送通道。
4. **撤回/禁言/解禁**：先在指定隔离测试群验证最小动作和未知状态，再接全群禁言、
   踢人、公告和名片。未知结果不能盲目重试或改成成功。
5. **其他读原语和媒体**：禁言列表、好友、邀请记录集中读取；媒体上传单独设置容量、
   校验与保留边界。关键词、规则、任务等业务模块只调用验收后的底座。

第1、2项必须作为同一开放门槛完成：只有发送编码或发送器实现，不能开放真实发送。

成员只读批次未新增部署服务、迁移或常驻名单缓存，未自动登录/发送/群管，也未重建 `wsl`。

## 下一批：文本出站基础（2026-10-27）

这是候选源码实现，不是生产发送开通。成员读取批次之后新增前向迁移018；
001–017不修改。未增加服务、依赖、前端按钮或原生HTTP写路由。

- `internal/nativewire/send.go`：纯群文本，固定 session=2/device=1/version=2，
  使用已核对桌面 Timestamp；同旧接入器的8字节nonce libsodium AEAD、
  LZ4长度前缀、Envelope和 `{"b":…}` 封装。完整应用protobuf最大4096字节，
  不是允许4096字节正文后再无限追加元数据；无私聊、媒体、引用或@回退。
- E34：依据本地固定参考 `astrbot-a672ef9/adapter.py::_text_message/send_text`、
  `wire.py::seal_message` 及官方桌面研究E33。NIM群发送固定8/2，属性仅
  0/1/8/10/11；回执要求7/12是规范正整数，11若存在必须匹配客户端ID。
  通道序号和回执共同关联请求，服务端接受不等于成员送达。
- `internal/gateway/send_text.go`：复用现有socket、单reader和不取模的序号分配器；
  没有新连接、HTTP、目录读取、登录或重试。控制事务在传输锁外完成，
  socket只在一次写出时串行。回复等待期间不持有数据库事务。
  晚到的合法8/2回执作为密封notice持久化，不当作群消息、ACK或恢复水位；
  本批不会据此自行将未知业务动作改为成功。
- `internal/control/native_text.go`：隔离测试专用 `Stage/Dispatch`，网站会话引用
  是唯一身份来源。验证当前超管、有效套餐与moderation模块、WSL账号、
  登录/接入/测试状态、账号epoch、有效连接租约/owner/revision及新鲜心跳、
  群归属/管理开关/绑定epoch、60秒内原生管理员观察和同一创建人的测试窗口。
  测试窗口没有越过套餐、授权或管理员要求的特权；租户与热群工作台不能使用。
- 意图及正文加密存入既有operations，沿用7天正文清理；幂等键冲突拒绝，
  每账号最多16个排队意图。018持久nonce高水位及每意图唯一客户端ID/
  nonce/AAD/回执。意图提交后才占一次测试次数并进入running，
  然后在单次socket写出前重新锁定并核验控制条件。
- 控制失效且尚未调用写出：failed/not_submitted；明确上游拒绝：failed；
  合法回执：succeeded/im_server_accepted；写出附近断线、取消、无回执或
  回执冲突：unknown。unknown/running不重发，账号有其他未决提交时拒绝新提交。
  最终证据保存失败返回待对账，不报告成功。
- `Expire`只把超时queued标记expired，把超过执行及证据保存宽限期的running
  标记unknown；没有重发或假定成功，也没有自动启动后台扫描器。
  清理账号/意图不能重置nonce高水位；备份回滚、旧系统nonce迁移和共用消息密钥
  的历史范围仍必须核验，不能仅靠时间初值宣称跨系统绝不复用nonce。

**仍关闭的接线**：`POST /api/v1/operations`继续返回
`native_compatibility_not_verified`；NativeTextService没有生产HTTP/worker注册，
`sendGroupText`没有真实账号调用者。测试传输口只使用合成消息和本机假服务。
读取成员弹窗仍不写可信角色表。本批最终控制测试使用隔离数据库内的合成
`account_groups`，不代表真实成员角色、当前可发言权限、传输群/身份映射已验收。

**下一开放门槛**：把当前唯一连接所有者、可信最新原生身份/群路由/可发言证据与
控制服务端到端适配，完成nonce迁移及未知结果对账，之后再取得明确范围授权做
隔离账号最小文本发送。上述未完成前，引用/@/业务模块不接入生产发送，
`native_ready=false`、`ai_ready=false`不变。

## 连接所有者与未知结果对账批次（2026-10-27）

本节补充上一批的内部接线，不等于生产动作入口开放。

- `ReceiverManager` 为每个 worker 关联当前 socket、连接生命周期、业务UID、
  NIM身份和部署版本。重连退出即移除关联；适配器不创建第二连接、不执行登录、
  不切换账号、不重发。
- `text_owner.go` 在账号读取调度中重新读取固定群目录及成员名单，不使用网页传入的
  team/身份或10分钟前的目录证明执行权限。只接受完整名单中唯一的本人、
  与连接匹配的NIM身份及明确admin/owner；目录或身份缺失、离线、租约/epoch/
  revision变化、取消均阻断。读取不进入ACK链路，也不自动写可信角色表。
- 保存精确出站密文附件的SHA256、team、NIM发送者、部署版本及采样时间后，
  才能进入最终控制栅栏。栅栏锁定部署版本并要求路由观察不超过5秒；
  写出前再次核对同一个 worker/socket 和有效租约。新的前向迁移019仅增加
  平台私有证据表，001–018不修改，租户数据库角色无权读取。
- `nativeTextPort` 是HTTP组装层的内部适配器，没有注册到生产操作路由或worker。
  原有 `POST /api/v1/operations` 继续拒绝。可信角色表更新、原生禁言/可发言
  状态及nonce跨旧系统/备份历史仍需完成，不用目录成员身份假冒完整权限验收。
- `NativeTextService.Reconcile` 先复核当前网站超管及同一操作创建人，从服务器
  加载不可变路由证据；查询期间不持有控制事务。gateway最多检查200条本账号
  近7天、提交后可靠保存的群回显，同时匹配team、发送者、客户端ID、原生格式、
  精确密文摘要和规范服务端ID/时间。私聊、其他账号、不同正文或路由不能对账。
- 找到唯一一致证据后，提交前再次复核网站会话、用户状态及账号epoch，事务保存
  回执和最小审计；重复对账不重复提交。结果仅表示 `im_server_accepted_reconciled`，
  不是成员送达。无证据、超过扫描上限、证据冲突均保持unknown，不推断失败、
  不补发。只有客户端ID的晚到8/2通知没有本批所需的完整路由/密文证据，不能单独
  把未知改成成功；原生平台不回显时仍需后续受控人工核对。

  浏览器不能提交tenant、原生ID或传输路由。未授权观察群明确阻断。
- `Stage/Dispatch/Inspect/Reconcile`沿用网站会话引用、持久幂等键、
  既有控制事务及精确回显证据。HTTP超时、5xx或断连保留待核对状态；
  恢复查询不重发，继续提交仍需确认，未知提交不重试。
- 草稿仅在32个内存作用域中保留，切换账号/群不会串草稿；切走再切回也不能让
  旧请求继续原生提交。卸载页面同样取消后续步骤，已提交结果仍需核对。
- `nativeTextTestPort`仅供合成验收夹具注入；生产组装始终为nil，无配置入口
  可绕过。默认返回`native_text_acceptance_pending`，UI显示真实原因。
  新入口没有发送真实账号消息，也未放开通用operations或业务worker。

## 恢复、可信角色与消息原语补齐（2026-10-28）

本批未新增迁移或原生HTTP写路由，没有启动真实账号测试。

- `RunNativeMaintenance`在API进程内每5秒执行数据库恢复，首次立即执行；
  每次最多100条、事务3秒、行锁等待750ms，使用`SKIP LOCKED`。
  queued过期转expired，running超过期限15秒宽限后转unknown。
  状态与`native_text_recovered`最小审计同事务；重启时原有running→unknown
  同样补原子审计。不会将unknown重排队、自动核对原生端或重发消息。
  取消后退出，数据库故障仅返回安全原因码，不阻塞接收、可靠落盘或ACK。
- 账号级`native-text-operations`恢复接口与会话投影、当前群绑定解耦，消息中心
  “核对状态/查询回显”改用该入口。网站会话、超管、原操作创建人及账号仍逐次校验；
  解绑或七天投影过期后仍可查最小状态，不返回原文、不延长保留、不提供提交入口。
  回显证据缺失或原账号epoch不符仍保持未知，不以恢复查询绕过发送授权。
- `nativewire.MutedMembersRequest/ParseMutedMembers`复用固定参考
  `nim.py::get_team_muted_members`的8/27协议；核对team、完整边界、
  最多10000条、唯一32位传输身份和明确禁言标记，拒绝截断、外群、重复和残留字节。
  当前连接读取后与完整成员映射核对；本人被单独禁言、无法映射或查询失败时拒绝发送。
  取消后的迟到8/27完整回复仅保留notice，不生成ACK或推进游标，不误伤接收流；
  邻近未知命令、截断或歧义格式仍阻断。这不证明上游全群策略及其他发言限制已完整支持。
- `ReceiverManager.ObserveRole`与文本提交共用目录、完整成员及单独禁言证据采集，
  复用账号读取调度、唯一socket及取消范围，不另建连接或缓存权限。
  新增超管POST`/api/v1/accounts/{id}/native-role`，浏览器仅可提交原生`group_id`。
  `control.RecordNativeRole`重新检查网站会话、账号业务UID/epoch、部署版本、
  接收owner/revision、租约、心跳及5秒证据期限，较旧观察不能覆盖新记录。
  5秒从首个原生读取前起算，慢分页不能把旧角色重标为“刚采样”。
  有效原生观察可以创建未认领群的身份记录，但不会创建租户绑定、授权码、测试窗口，
  不会启用群或提高readiness。角色变化复用既有epoch提升、旧排队失效及审计事务。
- 消息中心成员弹窗增加“核验当前身份”，明确确认后才采集；
  显示角色和单独禁言结果，关闭、切换账号、刷新或卸载阻断迟到结果。
  原`native-members`只读读取依然不会写权限表；未知/部分名单不构成可信证据。
- 群出站支持105字段的UTF-16精确@位置编码、14/301引用编码及29–38传输引用元数据；
  既有纯文本黄金向量保持不变。@UID和当前名片必须匹配完整成员；
  本节批次尚未接入可信引用，后续接线见下节；未完成组件不能只发送其中的正文。
- 私聊使用独立`PrivateText`业务peer契约、session=1及NIM7/1命令，
  不把群目标改成私聊，也不接受群专属@/引用。已补单次栅栏、相关回执和未知不重试的
  合成测试；没有私聊持久操作/API注册。群撤回仅补已核对的7/13编码，
  未注册任何撤回执行器。

**仍需真实输入的门槛**：旧系统/备份的nonce范围、共用密钥历史及恢复边界未提供，
不能靠微秒时间初值或网页勾选替代核验。真实验收还需明确账号、隔离群、目标、
允许动作、次数和期限；本批不自行选择运行账号发消息或群管。

**该批次未交付项**：私聊/辣椒聊持久发送、引用/撤回控制闭环、禁言/解禁/踢人的持久提交、

## 引用与 @ 的持久提交接线（2026-10-28）

本批接上已有协议原语与控制服务，不新增发送器、连接、迁移、依赖或部署服务。
候选源码可在合成测试口验证群引用和 @；生产组装的`nativeTextTestPort`仍为nil，
通用原生操作入口仍关闭。消息中心当前输入框仍为纯文本，没有伪装成已交付的引用按钮
或成员选择器。

- `TextRequest`增加可选引用事件ID、@组件与服务器捕获的原消息证据摘要；纯文本请求
  省略这些字段，保持旧请求摘要及已保存意图兼容。Stage与Dispatch复用原有幂等键、
  nonce高水位、测试预算、操作状态、未知结果对账与单次写出，不另建平行通道。
- 浏览器只能提交规范正整数`reply_to`和有界`mentions`，不能提交引用正文、服务端消息ID、
  NIM路由或证据摘要。服务器从同账号、当前部署、七天保留期内的已解码群消息读取引用，
  核对业务群、会话及文本格式。过期、未来、跨账号/群、私聊、坏密封或超长引用一律拒绝；
  引用正文不截断、不降级为普通文本。
- Stage捕获原始事件与投影密文的两个SHA256，密封意图只保存事件ID和摘要，不复制引用原文。
  Dispatch重新读取并比较；最终提交事务再次锁定原事件、投影和部署版本，
  保留期另留3秒写出余量。证据变化或到期阻断，不通过重投影延长原消息保留。
  解码投影AAD移至共享安全辅助函数，历史`native-decoded:<account>:<event>`格式不变。
- 当前唯一连接所有者独立解密原始事件及应用封包，核对业务群、NIM群、原发送者、
  客户端ID、服务端ID、时间和精确正文。原发送者必须在本次新鲜完整成员名单中唯一映射，
  已退群或映射不明时保守拒绝引用；不把历史消息身份当作当前权限证明。
- @最多32个，位置按UTF-16验证，UID及当前名片必须匹配完整成员名单。
  每个被@的UID还必须出现在本次测试窗口明确授权的`target_ids`中，
  Stage和最终栅栏均重核，取消目标或修改名片后不能继续提交。
- 引用通过现有8/2群发送及29–38字段构建器，只进行一次受控写出；回执仍只代表原生服务端
  接受，不等于送达或已读。断线/未知保持unknown，不因携带引用而重试。

真实原生测试数仍为0；nonce旧系统/备份历史、完整发言策略及明确授权隔离群验收仍是
开放前提。本批不包含私聊/辣椒聊持久发送、撤回、禁言/解禁/踢人的执行器、媒体、好友、
邀请或原生资料。网页交互与这些未完成底座继续分批交付，两个readiness保持false。
