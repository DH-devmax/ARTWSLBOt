# 原生消息接收器

群组/私聊的只读投影、中心化并发解码器、目录同步和独立健康指标见
[`native-conversations.md`](native-conversations.md)。
这些后台工作不进入收包/ACK 热路径，也不授予群管或消息发送权限。

## 辣椒聊原操作历史核对（2026-11-13）

RPC1005历史读取与固定OpenIM 3.8.3的`message_check.go`保持一致：
有合法范围序号、空`clientMsgID`的记录是历史占位，允许同批真实消息继续参与核对。
占位仍计入条数和字节预算，不能提供路由、正文或发送成功证据；真实缺号、
重复和越界序列、非法非空ID及超大记录继续拒绝。临时正文在检查完成后清零。

原未知发送的显式“查询回显”可以返回一次性`evidence_check`：
固定枚举区分未返回目标会话、空历史、未找到原消息、达到扫描上限及匹配成功。
仅含本次读取条数、会话数量和采样时间，不含消息ID、正文或凭据，不持久化、
不由刷新或轮询触发上游读取。未找到和截断不能解释为未发送，原状态保持未知；
只有原消息身份、正文摘要、路由、时间及服务端回执全部一致，才沿原账本核对。

## 本轮边界

原生身份已由用户手动登录成功。本轮接通独立的只收消息链路：
IM 握手、心跳、有界推送、可靠持久化后 ACK、断线恢复及账号实时指标。
登录成功不代表消息链路通过验收，不开启群管、发言或 AI。

实现顺序：

1. 核对锁定 AstrBot 的连接及消息契约，以合成回放验证编解码和时序。
2. 引入账号唯一连接所有者、会话读取与版本栅栏、接收专用启停入口。
3. 接通账号工作台的实际观测数据，执行故障和浏览器回归，再限定接收联调。

## 安全约束

- 切换工作台和账号不启动、停止或重登连接。
- 一个原生账号只能有一个连接所有者；会话、部署或账号失效即停止。
- 先启动接收再同步；群资料或成员 HTTP 不能阻塞接收和 ACK。
- 消息持久化提交成功后才 ACK，不因解码失败或数据库不可用跳过消息。
- 提交后通过容量为1的非阻塞通知唤醒解码器；通知不等待工作池、查询或浏览器。
  ACK 仍只依赖既有持久化与版本栅栏，不等待消息投影或 SSE。
- 原文加密保存，日志和监测不能返回凭据或消息正文。
- 原生接入及 AI 整体 readiness 保持关闭，单独说明接收链路验收范围。

## 实现

迁移 013 增加平台专用的 IM 配置、接收器控制/租约/水位及原始事件表；
租户数据库角色没有访问这些共享数据的权限。机器人删除通过外键级联
删除接收器和原始事件，删除预览列出相应数量。原文事件按接收时间保留 7 天。

一个协调器持有 PostgreSQL 会话咨询锁，每账号有独立租约和接收协程。
协调器失去数据库连接会取消全部旧 socket；替代进程必须等待旧账号租约失效。
数据库提交和 ACK 写出均核对账号 epoch、接收 revision、所有者及有效租约。
停用不删除原生会话，重启按持久化开关恢复。踢线、认证拒绝或未知边界进入
阻断状态，必须人工重新连接或停用后启用；不会持续争抢另一客户端的连接。

推送队列最多 32 包且最多 16MiB，提交批次最多 32 包和约 5MiB，
收集窗口 2ms；消息上限 1MiB。超限关闭流并从已保存水位恢复。
心跳每 15 秒，回复匹配使用 service/command/serial，序号到 60000 前停止
使用该连接，不取模。普通断线按 1–30 秒退避；429 遵守服务端 Retry-After。
静态认证先使用已保存 IM 令牌；动态/回调认证在每次连接前通过
已保存业务会话换票一次，不先提交可能已消费的旧票。换票保存仍核对
账号 epoch、接收 revision、所有者和租约；不自动注册、短信或密码登录。
回调认证按桌面契约将本次令牌另写属性 116，不拼接或改写持久化 token。
IM 认证拒绝不切换服务器或再次换票争抢；
结果未知、失效会话及验证要求阻断自动恢复。

## 启动与恢复稳定性

认证握手完成后先启动持久化消费者，再发送首个心跳和首次同步请求。
登录后集中下发的消息仍经过同一有界 FIFO，不让尚未启动的消费者阻塞心跳。
首次同步回复进入 FIFO，并在前序消息、水位提交及对应 ACK 写出后发出同步完成信号。
完成前状态为 `synchronizing`，完成后才置为 `connected` 并记录 `synced_at`；
只有新鲜心跳而没有该次连接同步证据时，健康度不能显示正常。
重连清除上次连接的同步和心跳证据，历史计数仍保留。

首次同步中的断网、超时继续按连接错误退避，不再误报为未知消息边界。
无法核验的消息边界仍隔离并阻断；消费者失败立即关闭 socket，
让等待中的心跳和同步请求收到实际错误，不把毒包错误覆盖为普通超时。
LBS 发现和 WSS 握手的 HTTP 429 都遵守有界 `Retry-After`，
不改用下一个消息服务器绕过该次限流；`retry_at` 显示当前进程的下次重试时间。
稳定完成同步至少 30 秒后，后续普通断线从一秒退避重新开始。
无法核验的换票回包也阻断，避免持续提交可能改变会话状态的请求。

总览状态表、顶部连接状态及账号工作台使用同一个人工“重新登录”流程：
先读取接收 revision 并停收，成功后打开同账号登录表单；停收冲突或失败不打开
表单，切换账号后的迟到停收响应也不会打开其他账号。
该入口只创建网站本地验证事务，不提交密码、短信、人机验证或原生登录，
不会清空已有会话。登录完成后仍需用户显式启用消息接收。
仅协议认证失败不要求用户重复密码登录：阻断面板提供“重新连接”，
按当前 revision 重新启用接收并清除旧阻断快照，沿用已保存业务会话。
上游业务会话确实失效或要求人工验证时才需要“重新登录”。

## 接口与观测

- `GET/PUT /api/v1/accounts/{id}/receiver`：超管接收专用开关，写入携带 revision。
- `GET/PUT /api/v1/native-im-profile`：超管维护独立 IM 配置；读取不返回 AppKey，
  有账号启用接收时禁止替换。
- 账号 dashboard 仅向超管附加共享接收器遥测；普通租户仍只读取原有 RLS 群指标。
- 2026-10-27 增加按账号/工作台隔离的 SSE：沿用既有每秒接收观察，轻量推送到页面，
  与15秒业务聚合分开更新；事件总线及浏览器队列有界，慢订阅不反压收包。
  消息连接本来就是持续 WebSocket 接收，不需要完整桌面程序或按页面频率读消息。
  事件流只含安全状态与资源编号，正文仍由授权查询获取；边界见消息中心文档。
- 协调与授权每秒检查；15秒租约每5秒续期，指标快照每5秒保存，状态变化及时保存。
  观测有效性依赖未过期租约及最近15秒内的协调器采样。续期的本地截止时间
  从发起数据库请求前计算，不能把数据库等待叠加到租约上；失效立即取消连接。
  心跳超40秒标记异常。账号运行状态仅在变化时写入，分位数最多每秒聚合一次。
- 接收/重复/ACK/重连计数属于本次接收器进程周期。落盘 P95 从收包单调时钟
  测至同步事务提交返回；ACK P95 测至 socket 写出成功，**不是服务端处理成功**。
  延迟只保留至多 1024 条最近样本；没有样本返回 null。
- 接收速率是最近 60 个一秒桶内已持久化收到的消息数 / 60（包含重复投递），
  与原有业务 inbox 的去重入库速率分开显示。
- `synced_at` 表示该次连接的首次同步已提交；它不是完整业务群映射或原生整体
  readiness。`retry_at` 不是持久化的跨重启调度承诺，永久阻断时为空。
- 认证诊断仅保留 `error_stage`（`im_token` 或 `im_login`）及安全数字
  `upstream_code`，区分业务换票拒绝与消息握手拒绝；不返回上游正文、令牌或密码。
  旧快照没有数字码，不能将测试中的 302 当作真实账号已观测结果。
- 本轮事件尚未与经过核验的业务群目录关联，全部暂停业务处理，不进入规则、
  排行、财务、AI。原有 dashboard 的业务 inbox 图表仍按原定义统计，不能把其
  空值当作接收链路无消息。

## 联调与限制

自动化测试只使用合成 WebSocket、合成协议向量及 `wsl_test`。
`tools/receiver_local_probe.py` 默认只读；只有显式 `--enable-receive` 才修改开关。
它登录本机网站控制面，不重放原生登录、不发送群消息或群管动作。

`tools/native_session_probe.go`是人工本机诊断工具，不进入自动化CI或生产镜像。
默认只核验密封会话与当前部署、原生身份及设备绑定，不发送原生请求。
显式指定账号和`--renew-token`时，只允许已启用但处于blocked、租约已释放、
目录读取空闲且不在冷却期的WSL账号执行一次换票；不创建原生登录或IM连接。
工具持有生命周期及账号/目录行锁，持久化分配业务请求序号，
按原epoch、接收revision和部署版本保存新密封会话，不输出任何令牌。
结果未知时不自动重试，也不清除接收器阻断。后续恢复仍走控制面的
版本化接收开关，由原唯一连接所有者重新获取连接令牌。

现有数据库在迁移前备份至忽略目录，SHA256：
`ec2943601ada95492f13a8b1a72bf70d484907970160e8d3082a3012e7b06b1d`。
该备份含用户刚保存的原生会话，权限 0600，未纳入 Git。

本轮不宣称 100 条/秒生产容量或 24 小时稳定性通过。原生重放窗口、完整业务
群映射、应用消息解密及角色目录同步仍需后续验收；不启用整体 native/AI readiness。

早先只收联调曾记录换票需要重新验证。用户随后已人工重登，
2026-10-26 修正前后只读检查均为 `blocked / im_auth_rejected`；
这是保留的旧阻断快照，不是修正版再次拨号的结果。离线核对该保存会话
绑定有效、使用回调认证（类型 2），不能再仅凭旧建议要求用户反复重登。
修正版部署不会自动解除阻断，需要在账号面板人工“重新连接”才会尝试新握手。
该历史快照当时尚无真实心跳、收包或 ACK；它不代表下述最新桌面连接状态。
若新尝试失败，应根据阶段/数字码继续诊断，而非无条件重复登录。

桌面独占迁移后，必须先导入独立核验的桌面配置，再由用户人工完成桌面登录。
配置、保存会话和实际消息拨号三层均拒绝移动版本；不能仅改版本字段绕过。
迁移保留账号、群绑定、历史消息及业务证据，并关闭接收及原生动作。
手机与桌面共存仍需手机侧独立确认，不能凭桌面消息在线宣称通过。
