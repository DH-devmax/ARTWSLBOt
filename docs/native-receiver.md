# 原生消息接收器

实施日期：2026-10-26，时区 Asia/Shanghai。

## 本轮边界

原生身份已由用户手动登录成功。本轮接通独立的只收消息链路：
IM 握手、心跳、有界推送、可靠持久化后 ACK、断线恢复及账号实时指标。
登录成功不代表消息链路通过验收，不开启群管、发言或 AI。

实现顺序：

1. 核对锁定 AstrBot 的连接及消息契约，以合成回放验证编解码和时序。
2. 引入账号唯一连接所有者、会话读取与版本栅栏、接收专用启停入口。
3. 接通账号工作台的实际观测数据，执行故障和浏览器回归，再限定接收联调。

## 安全约束

- 切换工作台和账号不启动、停止或重登连接。
- 一个原生账号只能有一个连接所有者；会话、部署或账号失效即停止。
- 先启动接收再同步；群资料或成员 HTTP 不能阻塞接收和 ACK。
- 消息持久化提交成功后才 ACK，不因解码失败或数据库不可用跳过消息。
- 原文加密保存，日志和监测不能返回凭据或消息正文。
- 原生接入及 AI 整体 readiness 保持关闭，单独说明接收链路验收范围。

## 实现

迁移 013 增加平台专用的 IM 配置、接收器控制/租约/水位及原始事件表；
租户数据库角色没有访问这些共享数据的权限。机器人删除通过外键级联
删除接收器和原始事件，删除预览列出相应数量。原文事件按接收时间保留 7 天。

一个协调器持有 PostgreSQL 会话咨询锁，每账号有独立租约和接收协程。
协调器失去数据库连接会取消全部旧 socket；替代进程必须等待旧账号租约失效。
数据库提交和 ACK 写出均核对账号 epoch、接收 revision、所有者及有效租约。
停用不删除原生会话，重启按持久化开关恢复。踢线、认证拒绝或未知边界进入
阻断状态，必须显式停用后重新启用；不会持续争抢另一客户端的连接。

推送队列最多 32 包且最多 16MiB，提交批次最多 32 包和约 5MiB，
收集窗口 2ms；消息上限 1MiB。超限关闭流并从已保存水位恢复。
心跳每 15 秒，回复匹配使用 service/command/serial，序号到 60000 前停止
使用该连接，不取模。普通断线按 1–30 秒退避；429 遵守服务端 Retry-After。
先尝试已保存的 IM 令牌，只有 IM 服务明确拒绝动态或回调令牌时，才通过
保存的原生会话换票一次；不自动注册、短信或密码登录；
结果未知、失效会话及验证要求阻断自动恢复。

## 接口与观测

- `GET/PUT /api/v1/accounts/{id}/receiver`：超管接收专用开关，写入携带 revision。
- `GET/PUT /api/v1/native-im-profile`：超管维护独立 IM 配置；读取不返回 AppKey，
  有账号启用接收时禁止替换。
- 账号 dashboard 仅向超管附加共享接收器遥测；普通租户仍只读取原有 RLS 群指标。
- 观测有效性依赖未过期租约及最近 5 秒内的协调器采样。心跳超 40 秒标记异常。
- 接收/重复/ACK/重连计数属于本次接收器进程周期。落盘 P95 从收包单调时钟
  测至同步事务提交返回；ACK P95 测至 socket 写出成功，**不是服务端处理成功**。
  延迟只保留至多 1024 条最近样本；没有样本返回 null。
- 接收速率是最近 60 个一秒桶内已持久化收到的消息数 / 60（包含重复投递），
  与原有业务 inbox 的去重入库速率分开显示。
- 本轮事件尚未与经过核验的业务群目录关联，全部暂停业务处理，不进入规则、
  排行、财务、AI。原有 dashboard 的业务 inbox 图表仍按原定义统计，不能把其
  空值当作接收链路无消息。

## 联调与限制

自动化测试只使用合成 WebSocket、合成协议向量及 `wsl_test`。
`tools/receiver_local_probe.py` 默认只读；只有显式 `--enable-receive` 才修改开关。
它登录本机网站控制面，不重放原生登录、不发送群消息或群管动作。

现有数据库在迁移前备份至忽略目录，SHA256：
`ec2943601ada95492f13a8b1a72bf70d484907970160e8d3082a3012e7b06b1d`。
该备份含用户刚保存的原生会话，权限 0600，未纳入 Git。

本轮不宣称 100 条/秒生产容量或 24 小时稳定性通过。原生重放窗口、完整业务
群映射、应用消息解密及角色目录同步仍需后续验收；不启用整体 native/AI readiness。

真实只收联调已执行：保存会话离线恢复绑定通过；IM 服务拒绝缓存令牌后，
业务换票返回需要重新验证。接收器持久阻断，没有自动密码登录、验证码重放或
进一步重试；尚未观察到真实心跳、收包或 ACK。需要用户在 WebUI 先停用消息接收，
重新完成一次原生登录，再启用接收后继续联调。不能将“代码和合成测试通过”
写成“真实账号已在线”。
