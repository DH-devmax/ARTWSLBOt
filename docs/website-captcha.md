# 网站登录与机器人接入滑块验证

更新：2026-11-08。v64已于17:38:12（北京时间）更新现有Compose的API／Web，
部署及四视口真实图片检查通过；镜像与完整结果见[测试报告](test-report.md)。

## 保护入口

登录页品牌为“A哥后台 - 机器人”，移除原平台说明页脚。网站登录在密码核验前
要求完成一次拼图滑块。机器人接入创建、本人确认机器人主动发送好友申请、旧授权码申请和
超管测试认领也要求滑块验证。读取进度、关闭弹窗和取消申请不执行验证后的业务操作。

2026-11-10 受控例外：服务端确认超管本人、本人演示空间、指定平台、双方账号和隔离群的
持久受控范围有效时，接入创建及该挑战的单条好友同意／拒绝免滑块，仍需本人点击确认。
客户端不提供可信免验证标志；后续从挑战读取范围并重新核验。范围到期、关闭、撤权、
账号版本变化或结果待核对时拒绝提交。登录、普通接入、旧授权及独立演示认领不享受此例外。
不增加全局关闭开关，缺少服务端明确投影时继续要求滑块。

原生平台登录及其官方验证码保持独立。网站滑块不授予好友审批、群邀请、群归属、
套餐权益或测试资格；后续操作仍使用原控制层的实时权限及持久执行检查。

## 服务端

参考本地“多租户平台接续 · 本地工作区”的 GoCaptcha 拼图生成方式，锁定
`github.com/wenlng/go-captcha/v2 v2.0.5` 和
`github.com/wenlng/go-captcha-assets v1.0.7`。所有者明确授权`deps=allow`后引入，
唯一新增间接模块为`github.com/golang/freetype v0.0.0-20170609003504-e2365dfdc4a0`。
保留已有`golang.org/x/image v0.32.0`，无其他模块升级；锁文件及第三方许可证同步。

`internal/webcaptcha` 负责生成适配和有界、进程内的临时状态。
`internal/httpapi` 负责网站身份、操作作用域、Cookie、HTTP 接口和提交前消费票据。
不增加 Redis、数据库表、采集进程或生产服务，不进入原生接收、解码及 ACK 路径。

挑战有效120秒，成功验证后票据有效60秒。每次校验消费原挑战，错位和重复验证均
不能继续使用；票据在业务处理前消费，密码错误、业务拒绝或请求结果不明时也不自动重放。
服务重启后未使用挑战及票据失效，用户重新验证。

挑战和票据绑定浏览器随机 Cookie、请求 Host、连接来源地址、用途及网站身份。
登录另绑定用户名；授权另绑定当前网站会话、租户、平台和适用的挑战／群编号。
Cookie 为 HttpOnly、SameSite Strict，HTTPS 部署沿用 Secure 配置。
不信任浏览器传入的转发 IP，也不通过更改工作区取得权限。

状态总量最多1024项，限流桶最多4096项；图片同时生成最多2张，无等待队列。
每连接来源地址每5分钟最多生成60次、验证120次；同一浏览器及会话最多生成20次。
挑战过期按访问清理，不为每个用户创建后台任务。缺失验证、生成失败、容量耗尽或
服务不可用均拒绝继续；不提供开发绕过开关、答案接口或前端万能票据。

响应仅包含图片、尺寸、初始拼块位置、随机编号及期限，不返回目标坐标。
答案、临时票据、Cookie、密码及好友验证正文不写日志、审计或数据库。

## HTTP 与前端

所有接口使用既有 JSON 响应封装，均禁止缓存。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/auth/captcha/challenge` | 为指定用户名生成网站登录挑战 |
| `POST /api/v1/auth/captcha/verify` | 校验拼块坐标并签发登录票据 |
| `POST /api/v1/human-verification/challenge` | 已登录用户生成指定授权操作的挑战 |
| `POST /api/v1/human-verification/verify` | 校验并签发当前会话、平台及目标的操作票据 |

登录提交 `captcha_ticket`。其余受保护入口使用 `X-Human-Verification` 请求头，
不向控制层参数、幂等摘要或原生协议中加入验证码字段。授权接口保留 CSRF、
Origin、网站角色及原有业务权限检查。

主动好友申请使用独立用途`group_binding_friend_send`，绑定当前接入挑战。
精确查找与目标预览不发送申请；同意发送前须重新完成此用途的滑块。
旧`group_binding_friend`票据不能用于新发送入口；退役的入站核验不接受新提交。

前端复用 Element Plus 作用域弹窗和滑块。鼠标、触摸和键盘共用原始图片坐标，
缩小视口不改变服务端坐标。取消、关闭接入向导、切换平台或网站身份后，
旧响应不能提交业务；失败和到期可显式刷新挑战，不自动重发登录、好友或群操作。

## CLI 与自动回归

`wslctl login-challenge`生成图片及私有挑战状态，人工读取并输入坐标后再运行
`login --captcha-x ... --captcha-y ... --password-stdin`。挑战状态与正式会话文件分开，
保持同一Cookie／来源，读取后原子消费；失败或结果不明不重试。旧无验证登录不再可用，
具体命令见[受控工具](controlled-tools.md)。

容器smoke实际检查GoCaptcha图片格式、缺失票据、错误坐标及重放拒绝。
密码与滑块成功路径由隔离HTTP回归中的固定生成器验证。容器和CI需认证的其他检查，
通过只允许`wsl_test`、固定合成用户名及既有身份的测试夹具建立短期会话，
仍验证真实`/me`、权限、CSRF和退出。夹具不进入生产镜像，不增加生产登录绕过，
不创建角色或授权；CI临时数据库覆盖文件及私有会话仅用于自动检查。
