# 基于原生底座开发业务模块

助手开放是独立的编译期适配与后端策略，不随业务模块接入自动开启。查询、配置建议、动作建议分别授权，见[Agent模块开发契约](assistant-module-development.md)。

更新：2026-11-14。面向旺商聊与辣椒聊的业务开发，先复用现有能力，再补业务闭环。
本轮增加独立自动规则消费器与正式准入；实现、部署和真实平台验收分别记录，
不能把保存配置理解为已运行。

基础群文本聊天的独立实现见 [缓存与基础聊天](cache-and-basic-chat.md)：
控制层拥有持久消费/发送，热群引擎仅给出文本建议。群管规则由独立消费者处理，
规则命中可抑制热群；各来源、平台准入、部署和真实账号验收单独记录。
客户邀请、群归属证明和权限上限见 [客户接入](customer-onboarding.md)。
管理后台、用户中心、超管本人演示权益及页面单次执行见
[工作区与演示权益](operator-demo-workspaces.md)。客户空间后台消费者始终使用客户权益。
超管本人私有演示空间使用独立服务执行上下文及空间权益，AI按
`workspace_demo / platform_workspace` 记入平台实际及冻结费用。
不得伪造网站用户或调用人类演示权益解析来放宽客户自动执行或费用限制。

## 一、所有权与能力边界

```text
原生接收 → 密封落盘 → ACK
                  ↓
             解码与持久投影
                  ↓
        业务消费器（独立、有界、可关闭）
                  ↓
             Go 控制层
                  ↓
       持久操作、最终校验、平台适配
                  ↓
             核对结果与业务记录
```

| 位置                                                                  | 应负责                                           | 不应负责                                    |
| --------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------- |
| `internal/features`                                                   | 业务目录、字段、平台依赖、消费者范围和独立验收   | 网络请求、直接启用功能                      |
| `internal/nativewire` / `internal/lajiaoliao` / `internal/nativeauth` | 平台编解码、认证、有限协议适配                   | 套餐、业务规则、跨群缓存                    |
| `internal/gateway`                                                    | 接收持久化、ACK、会话和原生适配、结果证据        | 把接收回调变成业务执行器                    |
| `internal/control`                                                    | 网站身份、群授权、套餐、版本、持久计划及最终提交 | 信任模型、浏览器或原生名册自报的租户身份    |
| `internal/assistant`                                                  | 单群查询、配置建议、动作建议                     | 直接执行、创建测试授权、SQL/Shell/通用 HTTP |
| `internal/assistantadapter`                                           | 有界 Eino 适配                                   | 在核心包引入模型框架                        |
| `internal/heatbot`                                                    | 有界文本建议                                     | 原生发送、数据库、财务或插件执行            |
| `internal/httpapi` / `web/src/wsl`                                    | 有作用域的接口、配置弹窗、本人确认与真实状态     | 以按钮隐藏代替后端权限或以保存代替运行      |

新增能力前阅读 [架构契约](architecture.md)。本轮控制层增加独立持久消费、任务、尝试及
正式准入。未经对应平台和动作验收的来源保持关闭。
`ChangeBus` 是进程内刷新提示，不是持久任务队列，不可依靠它保证业务不丢失。

## 二、先判断能不能复用

以 `internal/features/catalog.go`、`native_usage.go`、各平台原生定义和生成的
[功能目录](feature-catalog.md) 为准：

1. 只依赖 `foundation` 中允许业务消费者使用的原语；用 `NativeBusinessAllowed` 检查消费者边界。
2. 这个检查仅表示目录允许复用，不等于生产执行许可。仍要检查具体子项的平台支持、
   实现、生产准入、当前原生角色和目标约束。
3. 原生目录的 `usage_layer=manual` 是人工账号操作，不能为了方便挂到助手或业务工具。包括认证、隐私、
   好友人工审批及人工媒体入口等，具体归类随目录维护。
   正式业务来源 `source=manual` 则专指用户中心中已允许的群管动作，是独立维度；
   不因此扩大原生人工账号能力的业务消费者范围。
4. `excluded` 不接入业务。收到相关消息仍须安全识别，不能因此阻断接收。
5. 辣椒聊保留字符串身份和原生消息 ID，不能套用旺商聊数字 ID、nonce、AAD 或验收证据。

同一父能力中的子项分别验收。例如“接收图片”通过不表示“上传图片并发送”通过；
用户 App 演示不代替本站发送验收；指定测试群通过不代替生产异常恢复。

## 三、业务目录与开发顺序

以下依赖是当前目录的摘要，开发时仍须读取平台实际返回；不能复制此表作为执行白名单。

| 模块                     | 原生依赖                   | 当前开发边界                                      |
| ------------------------ | -------------------------- | ------------------------------------------------- |
| 拦截词                   | 接收、角色、撤回          | 单词任一命中或启用组合的2至5词全部出现，仅撤回普通成员当前消息 |
| 黑名单                   | 接收、成员、角色、成员禁言 | 普通成员发言后禁言10分钟；周期内不重复提交，与永久禁止进群分开 |
| 豁免名单                 | 成员、角色                 | 只能豁免业务规则，不能绕过权限、套餐和原生角色    |
| 关键词回复               | 接收、角色、群文本         | 按保存顺序选首条启用的包含／完全匹配规则，单条文本不超过4000字节；群冷却默认30秒，可设置30至86400秒 |
| 图片回复                 | 接收、图片发送             | 不展示尚未实现的可操作配置                        |
| 定时发布                 | 群目录、角色、群文本       | 需持久调度、时区、错过策略和重复执行核对          |
| 消息排行                 | 接收、成员、群文本         | 需明确消息类型、时间窗、去重和发布契约            |
| 自动名片                 | 成员、角色、成员名片修改   | 需有界目标读取及权限变化恢复                      |
| 好友接入与原生主动申请    | 接入向导／受控测试         | 接入向导按昵称和服务端时间定位单条传入申请，本人确认后同意，身份仍由认证私聊证明；原生搜索和主动申请仅限超管持久受控测试，不向助手、自动群管或热群开放 |
| 活动抽奖                 | 接收、成员、群文本         | 现有 WSL Web 管理不代表群内报名、发布已接通       |
| 邀请记录、邀请奖励、返现 | 成员、邀请历史             | 缺失邀请证据不能推断归属或直接记奖励              |
| 财务台账                 | 不依赖原生执行             | 现有 WSL Web 追加账，不是支付、自动转账或返现闭环 |
| 热群机器人               | 邀请、接收、角色、群文本   | 申请、模型建议、实际发送分别验收                  |

`CatalogForPlatform` 决定各平台可见模块；目前不要把 WSL 的财务、抽奖入口直接复制到辣椒聊。
建议先完成拦截词、名单和关键词回复，再推进定时、排行等；每个模块单独开关、限流和验收。
人物印象、长期记忆、表达学习等是可选扩展，关闭时不能订阅正文、分配队列或参与解析热路径。

## 四、复用现有配置事务

现有接口：

```text
GET /api/v1/features/catalog
GET /api/v1/groups/{group_id}/features
PUT /api/v1/groups/{group_id}/features
POST /api/v1/groups/{group_id}/features/preview
```

使用产品现有平台/账号视图和网站会话；路径中的群 ID 不是授权。
提交仅包含当前模块的变更及当前配置版本。以下仅示意请求形状，版本与字段必须来自实际读取：

```json
{
  "version": 12,
  "changes": {
    "keyword_replies": {
      "enabled": true
    }
  }
}
```

配置入口在 `internal/control/feature_config.go`：

- `ValidateFeatures` 复用目录、字段、权限和格式校验，不信任客户端隐藏字段。
- `SaveFeaturesTx` 复核群、平台、当前绑定、套餐和字段权限，使用现有事务与版本栅栏。
- `CommitGroupConfigTx` 更新版本与 epoch，取消失效排队工作并记录安全审计。
- 返回 `applied:false` 表示配置保存，不表示运行。界面必须分开显示“保存启用”与“实际运行”。

内容字段、名单上限和回复规则结构以目录及校验代码为准。新增字段同步：
目录、校验器、字段权限、编辑器、冲突处理、生成目录与测试。
不要增加一个绕开现有事务的“快捷保存”接口。

2026-11-14 的规则扩展和远端功能对照见
[AstrBot 功能适配](astrbot-wsl-function-comparison.md)。组合规则字段为
`blocked_words.rules`，关键词冷却为 `keyword_replies.cooldown_seconds`，
分别继承现有字段权限与租户上限。旧 `PATCH /groups/{id}` 不拥有这些新增字段，
省略时保留原值，不能借旧表单清空。

`features/preview` 使用相同校验和当前版本，只返回模拟判断；只读成员只能检查已保存
规则，有草稿时继续检查编辑权限。不得把模拟的成员／角色当作原生证明，不得在试算、
刷新或关闭弹窗时保存、创建任务、读取原生名单或执行动作。新增字段不因目录登记自动
进入助手 `ContentField` 白名单。

## 五、实现自动业务闭环

`internal/control/business_rules_*.go` 实现首批规则消费与执行，
`internal/features/business_rules.go` 保存纯匹配规则。受控发送服务和助手本人确认记录
不能直接当成自动业务执行记录。

1. 从持久投影增量读取已授权事件，记录消费进度；ACK 不等待规则、模型、成员目录或发送。
2. 在读取正文和创建任务前检查功能是否实际启用。关闭项应零业务任务、零模型调用、
   零原生读取；不要每群创建常驻 goroutine、定时器或连接。
3. 用租户、平台、账号、群、源事件、规则版本及具体动作构造稳定幂等键；
   同一规则命中重放不能产生第二次有效提交。
4. 生成有界业务意图，交控制层持久化；来源、配置版本和必要参数密封保存。
   不复制整个聊天历史，不跨任务缓存明文凭据。
5. 补独立普通业务准入。禁止复用超管测试窗口、`native_debug` 或伪造网站本人确认。
6. 在最终提交处重新读取授权、绑定、套餐、账号 epoch、配置版本、原生角色、目标、期限。
   排队前检查不能代替最终检查。
7. 只对已确认成功提交的动作发布通知。超时或提交结果不明时保留原操作编号核对；
   断线、重启、重复消费均不得自动重新发送。
8. 成功、拒绝、失效、取消、未知分别持久记录；业务结果不能只看 HTTP 200 或请求已受理。

如需新增持久任务状态与表，先设计并评审，再使用下一未占用前向迁移。不可修改已应用迁移，
也不要把设计中的任务状态写成“当前系统已经支持”。

助手配置建议继续用现有配置事务；助手原生计划复用不可变密封计划和本人确认入口。
`internal/features/assistant.go` 的每平台 `Production` 状态必须独立核验；
正式准入由控制层按平台、动作、来源和指定群核验，不得因受控记录通过而开启。
后台模块不能冒用助手审批。

消费者使用既有连接池和原生调度，最多4个执行、64个等待；每租户2个执行、
8个等待，每群1个执行与1个等待。任务120秒过期，账号原生变更串行且间隔至少5秒。
启用前历史不执行；晚提交回扫与去重记录共同防漏。只有潜在命中才读取新鲜原生角色，
关闭项和字面匹配未命中项不发原生查询。接入挑战、号池机器人和不适用消息被过滤。
群主、管理员与豁免成员不自动处置；命中处置优先于关键词回复，相关命中抑制热群。

## 六、隔离与性能要求

- 网站用户及租户来自认证会话，账号从有效群绑定解析。普通成员只访问明确分配的群。
- 查询、历史、事件、计划、确认、最终提交都复核范围；撤权、换绑、版本及 epoch 变化停止旧工作。
- 缓存、草稿、游标按用户/租户/平台/账号/群隔离；迟到响应不得污染新页面。
- 接收连接按账号维护，现有解码为 4 worker、16 项队列及独立 4 连接池。
  不为每个业务、每个群复制解析器或数据库池。
- 优先复用持久投影，不重新解密原始消息。成员和角色通过现有有界读取调度获取，
  最终授权使用新鲜证据，不用陈旧快照放行。
- 100/300 群是构造规模和授权范围，不是容量承诺。记录消息速率、热点、队列、数据库等待、
  完整服务 P95 和样本时间；合并原始样本，不平均各账号 P95。
- 保留既有未知字段、大小、UTF-8、签名、nonce、租约和恢复检查。
  不用丢消息、移动计时边界或跳过格式验证换取“提速”。

## 七、前端基准

目录只读显示已保存配置；功能开关、内容和业务操作在作用域弹窗编辑。
复用 `FeatureCenter.vue`、`BusinessModuleDialog.vue` 和现有编辑器，而不是嵌入上游管理页面。
草稿按操作者/平台/账号/群保留，保存只写当前模块；版本冲突保留草稿供核对。
查看、关闭弹窗、选群均不得提交。

配置保存、运行开关、不可用原因、上次执行结果分开展示。
不可用控件不伪装可操作；未知结果只提供原操作查询。
确认文案具体到群、机器人、目标和影响；320/390/768/1440 视口验证正文滚动和可见底部操作。

## 八、完成清单

- 更新 `internal/features` 的平台定义、依赖、消费者范围和验收证据。
- 运行 `go run ./tools/feature_catalog -write`，通过目录同步测试。
- 覆盖纯规则、输入上限、幂等、禁用零工作、跨租户、未分配群、撤权、版本与 epoch 变化、
  取消、未知提交、重启恢复及并发预算。
- 合成协议测试不接真实群、不认证、不发短信。数据库仅串行使用隔离 `wsl_test`。
- 真实业务验收先建立指定群正式灰度，再走正常业务入口；独立受控工具另按持久授权
  限定自有账号、测试群、动作、目标、期限和预算。两种入口不能借用彼此准入，
  不批量操作或自动补充次数。
- 完成 race/sodium、架构事实与仓库守卫、隔离 PostgreSQL、产品前端、容器 smoke；
  结构变化更新架构证据及匹配可信基线的 CodeBoarding。
- 测试、真实动作和生产准入分别记录到 [测试报告](test-report.md)。只部署本轮已验证白名单，
  不混入其他未发布解析、媒体或轻量化候选，不自动改变 readiness。
