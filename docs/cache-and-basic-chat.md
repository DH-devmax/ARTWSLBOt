# 双平台缓存与基础聊天

实现日期：2026-11-04。实现、合成检查、部署和真实群验收分别记录于
[测试报告](test-report.md)，本文不是生产容量或 readiness 声明。

## 读取缓存

`internal/scopecache` 使用标准库实现进程内 TTL/LRU。旺商聊与辣椒聊各有管理、
聊天两个分区，每区最多 256 项和 4MiB 载荷，每账号 32 项，单项超过 64KiB
直接交付、不存储。缓存未增加服务、连接池或每群常驻任务。

只读成员候选投影缓存 5 秒；版本化聊天设置仅以密封字节缓存 30 秒。
成员投影中的 `SelfRole` 固定为 `unknown`，不能充当执行角色证明。
权限、套餐、凭据、nonce、正文和模型回答不进入此缓存。

键包含平台、用途、账号、群、租户、网站用户、账号 epoch/version、
绑定/config、接收器 revision、部署版本和连接所有者。无空作用域或跨区回退。
每个调用者在入口与交付处分别复核权限，命中及合并结果仍重新核对实时版本。
成功保存后主动失效；通知遗漏不能绕过版本检查。
连接所有者取自数据库中的接收器记录，并与当前进程共同绑定缓存键。
交接后新读取不命中旧分区条目；读取中发生交接，旧结果在交付前被拒绝。

执行中合并只用于白名单投影。每个等待者独立取消，最后一个等待者退出才取消
共享读取；失效中的旧读取不能覆盖新值。底层继续使用每账号串行、全局两个读取槽。

辣椒聊的连接同步缓存独立于显示缓存：持久游标确认提交后更新，水位复用最多
四批或一秒；提示、重连和提交不明时重新读取。旺商聊不使用这套协议状态。
`CodecVersion=7`、解码器和 ACK 计时边界保持不变。

## 基础聊天

```text
原生消息持久化 / ACK
  → 控制层扫描当前聊天账号的授权群投影
  → 唯一消息决策 / 有界持久候选
  → 热群引擎文本建议 → 共享 AI 网关
  → 已结算费用与实时作用域校验
  → 独立持久发送尝试 → 现有连接 / 最终栅栏
```

该链路不消费群管规则、管理工具、记忆、人物印象、学习或插件。
热群引擎仍不依赖数据库、原生传输或控制层，也不能申请测试授权。

- 只读取绑定的 `purpose=chat` 账号收到的群文本；跳过自己、号池机器人、通知、
  私聊、纯媒体和已决策事件。原生 @ 和引用本人已发送消息属于定向触发。
- 群活跃度覆盖账号概率；无群配置默认 10%。活跃度 0 只关闭随机参与。
  账号关闭优先，账号/群时段取交集，冷却取较大值，默认 30 秒。
- 北京时间的群结束分钟包含在区间内，00:00–23:59 为全天，跨午夜环绕。
- 全局四个执行槽、每租户两个，等待总量 64、每租户八个；每群一个执行与一个候选。
  定向候选优先，候选 120 秒过期，生成最长 90 秒，账号原生写入至少间隔五秒。
- 本群最近 40 条，正文总计最多 32KiB，按需解封。生成仅允许单条 4096 字节文本，
  超限失败，不拆条、不自动重发。

迁移 `048_heat_chat_runtime.sql` 增加消费起点、去重决策、任务、独立发送尝试、
账号冷却及平台准入。扫描时间窗口和未处理回扫覆盖低 ID 晚提交。
配置、作用域与发送身份不可变；发送前重新核验所有者、群、套餐、角色、版本和租约。
旺商聊共享已有 nonce 账本，辣椒聊保持字符串身份及独立回执。

每任务只兑换一次模型凭证，兑换期限 30 秒与生成期限 90 秒分开。
共享 `ai_calls.external_key=heat-job:<任务ID>`，不增加第二份计费账本。
缺失 usage 冻结原费用且禁止发送。重启将可能提交的生成/发送置为 unknown，
不会再次生成或发送；发送核对只比较原任务的客户端 ID、群、身份与回显正文。

2026-11-06增加本人演示空间后台权益：控制层从实际空间及其有效超管所有者构建
`WorkspaceServiceContext`，不借用网站会话。本人显式启用的空间任务使用
`workspace_demo / platform_workspace` 记录真实任务、实际费用和冻结费用，
不扣客户钱包、不使用网关测试额度，仍受平台总预算约束。客户空间任务继续检查
套餐、钱包及原额度。生成、交付和发送重新核验空间、运行、聊天账号、版本及准入；
个人不限额不豁免号池容量、并发、冷却和原生角色。

## 接口与启用

现有群申请和配置接口继续使用；保存设置不会隐式启用账号或平台。
群配置读取补充：

```text
GET /api/v1/groups/{id}/chat-runtime
  effective_settings / runtime_state / blocked_reason / sampled_at
```

超管独立接口：

```text
PUT /api/v1/heat-chat/admission
  platform / enabled / version / evidence_sha256
POST /api/v1/heat-chat/jobs/{id}/reconcile
```

平台准入初始关闭。启用须记录对应平台验收证据摘要，由网站超管明确提交，
不自动修改 `native_ready` 或 `ai_ready`，也不自动启用任何群。
群申请须仍有聊天账号、套餐、群授权、原生身份和设置；缺项返回阻塞原因。
普通聊天不接受测试窗口或 `native_debug`。

部署按缓存、关闭状态的聊天两个阶段进行；只使用现有 Compose 服务并保留上一镜像。
真实验收须分别有已登录聊天账号和对应测试群；管理账号身份不能复制为聊天账号，
不能为补前置条件自动登录。

## 开发与验收入口

- `tools/cache_chat_candidate.mjs` 将本次白名单差异叠加到冻结 v49，而非发布整个工作区。
- `tools/cache_chat_checks.mjs` 对冻结清单分别执行代码、数据库、性能、浏览器及咨询检查。
  数据库性能使用 `wsl_test` 的实时版本查询和合成原生读取端口，不连接真实平台。
- `tools/cache_chat_deliver.mjs` 核对检查结果、未决提交、配置摘要和上一镜像后交付；
  聊天阶段必须有两平台关闭记录和零聊天任务。
- 缓存核心的 30 分钟观测可复用到后续候选，但必须逐文件核对被测实现与负载源摘要，
  保留原候选路径和日志。其他源码的检查结果不能这样继承。

监控折叠区只显示四个固定分区的命中、合并、淘汰、容量及聊天汇总计数。
不按账号、群或用户生成监控标签，也不记录正文、提示词和兑换凭证。
缓存命中仍需要实时数据库版本读取；原生读取减少不等于数据库请求减少。
微基准与合成持续负载不能证明真实百群容量、全天稳定性或旧解码性能目标通过。
