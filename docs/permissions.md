# 权限与作用域

## 受控接入范围

超管账号的受控测试布尔值只是总开关，不能替代持久授权。接入测试另须本人、
自己的演示空间、平台、双方不同账号、隔离群、epoch、版本和期限完全匹配。
测试证明独立标记 `controlled_test`，另一超管、普通客户及后台请求不能借用。
来源准入和原生动作授权仍各自核验；助手与热群不获得范围管理或 native_debug。

页面、助手及后台任务携带不可变范围快照，生成、交付和最终提交均重新检查。
关闭、到期或账号变化后拒绝旧工作，扫描清理有延迟也不能继续提交。
范围共享最多两次原生变更、两次模型调用及0.02 USDT预留，失败和未知结果
占用预算，不借续开重试旧操作。测试后台仍按平台演示费用记账，不扣客户钱包。

| 对象/动作 | 超管 | 租户用户 | 实际放行条件 |
| --- | --- | --- | --- |
| 网站用户、套餐、手动续期 | 管理 | 禁止 | 服务端角色 |

| 原生操作、AI 发言 | 按来源维护关闭/指定群灰度/开放 | 按本群有效权限提交 | 平台正式准入、套餐、绑定、运行开关及当前原生角色 |
| MaiBot 插件、工具、升级、系统接口 | 尚未暴露 | 禁止 | 未完成作用域适配前不能连接租户消息 |

## 管理与使用

管理后台负责审核、系统高级权限与号池维护；日常业务使用进入用户中心。
同一账号切换视图不改变授权或原生连接。超管本人在用户中心使用服务端生成的永久
“超管专属 · 不限额”，商业群数、成员数、个人积分与助手次数不限额；不生成付费订单。
页面和助手的单次动作仍受各平台 `manual`／`assistant` 正式准入、有效绑定、
归属证明、账号 epoch、当前原生角色及频控约束。

超管本人不继承目标客户的套餐、字段和动作上限，也不要求客户自动业务开启；
实际保存仍修改该客户的所选群。演示 AI 成本记入平台总预算，不扣客户钱包。
客户空间的自动群管、热群和客户本人继续执行客户权益交集；网关测试保持原测试预算。
每名超管有独立 `operator_demo` 空间，默认用户中心只显示自己的演示群。
显式查看全部客户授权群不开放其他超管的私有空间。普通客户不能取得专属套餐或加入演示空间。
本人空间后台业务由本人逐群启用，控制层使用 `WorkspaceServiceContext` 解析空间权益，
不伪造网站用户，也不借用人类演示权限。后台AI费用使用
`workspace_demo / platform_workspace`，与本人助手费用分开统计，计入平台总预算。
客户空间仍使用客户套餐和钱包；单次演示不会开启客户后台业务。
详情与接口见 [工作区与演示权益](operator-demo-workspaces.md)。

好友接入仅在独立准入下按确切昵称和服务端10分钟窗口定位唯一传入申请，本人确认才同意一次。
昵称、时间和好友关系均不证明身份；认证私聊及群内独立挑战和当前群主／管理员核验仍必需。
读取进度、刷新和GET均不审批；未知提交只能核对原尝试。助手与热群不获得好友审批工具。
普通用户的账号搜索与主动好友申请入口停用，原生底座仅向超管持久受控测试授权开放。

## 助手选群与认领

普通客户的助手目录只包含归属证明有效、且本人获分配的群；共享机器人和旧绑定
不代表已认领。群归属暂停或撤销后，旧会话、历史、工具、建议及确认继续重新校验。
超管可查看有效客户绑定和自己的演示群；未认领群明确为只读，不能提出或保存变更。

超管本人的有效测试认领可临时允许配置和单次动作建议，不建立客户群归属，
也不启动自动群管或热群。测试认领最长10分钟，绑定网站用户、账号和群的版本；
本人配置保存推进绑定版本和epoch后，旧计划仍失效；控制事务只为该本人创建
同范围、原到期时间的后继测试认领，不续期。其他人修改、撤权、换绑和到期
仍需重新核验；取消旧编号不能误报当前后继已解除。
配置表单、助手审批及旧完整配置接口共用控制层认领栅栏；原生动作还需各自正式准入、
当前原生角色、幂等、期限和频控。能力说明是快照，最终提交重新判断。

## 数据库边界

- 迁移连接为 `wsl_owner`。运行 API 只持有非超级用户 `wsl_platform` 和受限 `wsl_tenant`。
- 租户查询使用 `SET LOCAL app.tenant_id` 和会话可信 `app.actor_id` 的只读事务；
  群业务表叠加用户范围的 restrictive RLS，连接池不会保留前一个请求的设置。
- `tenant_id` 取自网站会话，不能通过查询字符串、前端提交的租户字段或资源 ID 推导访问权。
- 平台写入路径显式核验所属租户；租户池没有业务表写权限。RLS 是纵深防御，不是跳过应用授权的理由。
- 普通用户看不到全平台账号、其他租户群、共享密钥或原始接入数据。
- `ledger_entries` 对平台运行角色也撤销 UPDATE/DELETE；更正必须新增调整记录，不能覆盖已支付历史。
- 活动成员、账务与操作具有复合租户/群外键，避免平台写入错误作用域。
- 共享 MaiBot 账号不能作为群管账号，反向也不允许；数据库绑定触发器拒绝错池身份。
  旧绑定不静默迁移，若仍指向旺商聊群管账号，新的 AI 启用申请会要求超管人工复核。
- 租户数据库角色不能读取 `personas`、`user_access`、`maibot_settings`，也不能枚举热群账号。

## 工作台与账号

- `X-Workspace: wsl|lajiaoliao|maibot` 是查看范围，不是授权凭据；不传时为 `wsl`，未知值拒绝。
- 热群机器人入口与 API 均限超管，工作台白名单开放账号、认证、人设、只读聊天群、
  账号级聊天/模型/学习/记忆配置、安全配置日志、能力清单及系统监控；
  用户、套餐、群管、财务、操作与测试接口不能从 MaiBot 工作台调用。
- 账号路径与开户请求体中的账号 ID 必须属于当前工作台。前端切换不修改账号 epoch、会话或连接开关。
- 新账号在统一认证表单中命名并创建；群管、热群各池跨平台共享10账号，每账号30群；
  平台最多300个管理授权群，热群只能覆盖这些群。
  两池不能重复占用同一个原生身份；聊天授权仍由群管工作台与套餐统一核验。
- 模型密钥加密保存、读取隐藏、留空不覆盖、显式清除；配置草稿不存密钥。
  保存配置返回 `applied=false`，不启动模型或原生动作。
- 在线状态来自当前接收器所有者、租约和新鲜快照。受控测试账号动作开关不能
  代替正式业务准入，也不是实际连接是否在线的依据。

## 用户级权限

参考 `agent-desk` 固定 SHA `9f211c0d799ebc57463d465fc7a34ce39a9e3754` 的权限目录、
角色模板与用户分配方式，适配为当前 SaaS 的后端权限代码，未复制其源码。

- 超管在「用户管理 → 权限」选租户管理员、运营人员、只读用户，或逐项勾选自定义权限。
  管理员包含租户安全权限；运营人员不含财务写入与撤销授权；只读模板仅包含读取。
- `GET /access/catalog` 提供权限目录与模板，`GET/PUT /users/{id}/access` 读取/版本化修改。
  任意自定义角色不能授予平台超管、原生认证、全局配置或 MaiBot 工作台权限。
- 有效权限取平台准入、套餐、超管能力上限、租户授权、成员群范围及字段、
  群运行状态和当前原生角色的交集，每次请求由后端重新计算。
  历史查询不随套餐到期消失；规则、名单、回复等字段的变更按所属模块单独检查。
- 功能管理增加 `feature:<功能 ID>:<字段>`，支持对启用、仅管理员触发、规则分别分权；
  旧 `groups:replies` / `groups:moderation` 为宽权限。严格字段分权的自定义用户不能
  同时获授这些宽权限。功能与接口细节见 `feature-center.md`。
- 迁移025把旧管理员回退和既有群范围写成显式记录；运行时不再有无记录即管理员的回退。
  旧主账号必须由超管确认，新成员默认无群。主账号可管理成员、角色、覆盖与群分配；
  旧 `members:manage` 委派不能再创建、分群、禁用成员或重置其密码。
  超管管理成员时明确选择租户，不能从群名单推导网站所有权。
- 角色和个人覆盖先计算、明确拒绝优先，再取群、套餐、功能、原生角色和验收门槛的交集。
  覆盖支持到期；字段拒绝同时关闭可能绕过它的旧模块宽权限。
- 权限、密码、角色、成员状态或群分配更新使用版本号，撤销相关网站会话及订阅、
  取消该用户未提交操作和助手回合；实际提交与结果交付继续重新检查。
  原生提交处再次核验，结果未知只查询原操作编号，不自动重发。
- AI 入群/启停申请事务校验归属、有效 AI 模块、租户名额及平台300群上限，使用持久绑定；
  没有验证通过的邀请器/引擎时只保存待处理申请，`ai_enabled` 始终为 false，不创建已执行动作。

## 尚未开放的表面

2026-11-07起，助手能力同时要求平台显式开放和模块类别权限：
`assistant_module:<module>:query|config_propose|action_propose`。
这些权限不从旧角色或已有业务模块自动继承；租户上限、成员群范围、
业务权限、套餐与字段权限继续取交集。查询使用读取权限，不依赖编辑权限。
负责人只能分配超管开放及租户上限以内的权限。超管演示权益不绕过平台开放、
正式动作准入、群绑定、原生角色、账号epoch、幂等或频控。

`GET/PUT /api/v1/assistant/module-exposure`仅超管可用，按平台CAS更新。
策略版本进入回合及新计划的密封内容／摘要；关闭或修改后，旧回合、未提交计划、
SSE和迟到结果重新核验，不能用新授权追认旧计划。已提交原操作保留查询，
仍须当前资源及业务权限；旧正文不会随结果查询恢复。模块开放不会启用自动业务，
助手始终无法取得受控测试授权。接入契约见[模块开发](assistant-module-development.md)。

群管助手使用单群有界会话。`assistant:use/propose/approve`
均不从旧管理员模板继承；用户须显式授予且拥有 `management_assistant` 套餐。
PRO 的积分与热群共享，旧 Token 台账不转换。历史也重检用户、租户、群、字段和套餐；授权指纹改变后
正文和工具结果一并拒绝交付。配置审批只保存本人单群建议，重新检查字段和新鲜原生角色。
仅四类已实现规则支持开关建议，不包含AI、账号或财务配置。
原生建议、本人确认和每种动作分别要求 `assistant:action_propose`、
`assistant:action_approve`、`group_action:<action>`。四种助手模板为只读、配置建议、
配置本人确认、群管本人确认。最后一种只授予建议与确认流程，具体动作须逐项
选择；旧角色和旧授权不会自动获得新动作权限。
普通用户业务准入独立于受控测试，生产门槛未过时阻断提交，不能借用测试窗口、
native_debug或超管的授权。详情见 `management-assistant.md`。

首批后台规则仅包含拦截词撤回、业务黑名单禁言、豁免与关键词文本回复，采用
独立持久消费及正式准入。接入向导、助手、自动规则、热群和受控测试分别判断；
已实现或合成通过不代表真实平台验收通过。部署和灰度状态见 `test-report.md`。
商业套餐、统一网关、精确计费与兼容回退见 `commercial-billing.md`。
# Cross-platform user center (2026-10-27)

`/api/v1/workspaces` exposes only allowed panel entries; maibot remains
superadmin-only. `GET /api/v1/user-center` is bound to the website principal,
not a supplied tenant ID. Group/claim/operation collections intersect the
corresponding existing grants and tenant RLS. Published persona projection
requires `groups:ai` and an active AI package supporting that platform; it
never returns prompts, credentials or global engine configuration.

`PUT /api/v1/groups/{id}/chat-preferences` requires live `groups:ai`,
an active same-platform authorized group and AI package, CAS binding and
preference versions. It caps the per-group budget at the package budget and
only accepts a published chat persona on the same platform. Saving increments
binding epoch/version, cancels queued operations and audits metadata in the
same transaction. It does not enable native/chat execution.

LajiaoLiao login/challenge/session management and shared native conversation
views remain superadmin-only. A panel header cannot relabel an account,
resource IDs do not grant access, and historical reads do not authorize writes
after package expiration. Existing tenants are WSL-only unless explicitly
assigned a plan that includes LajiaoLiao.
