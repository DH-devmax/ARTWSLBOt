gopsutil/v4 固定 v4.26.9；Linux适配包仅使用当前PID的MemoryInfo方法，
CPU时间读取当前PID的stat，启动时间结合CLOCK_BOOTTIME和SC_CLK_TCK计算。
原因是该版本Times/CreateTime会间接执行虚拟化发现，读取modules/cpuinfo/environ等；
本轮禁止调用这些路径，也固定/proc来源而不接受环境覆盖。
另保留该版本的本地源码替换，只删除cpu包导入时的整机采样初始化，
避免即使仅调用RSS也触发宿主CPU读取。源码、许可证和补丁说明位于third_party，
构建与测试统一使用，架构守卫检查此约束。
由程序入口注入，非 Linux 不回退执行命令。原纯监控/热群核心依赖守卫保留。
无宿主机指标、进程枚举、命令行/环境、网络连接或其他项目采集。
Web、PostgreSQL 不展示进程资源；不展示项目总 CPU/内存。

HTTP/SSE 读取共享缓存。两个 Go 服务分别有一个采样循环，不按用户或群创建。
热群快照固定地址、1秒超时、16KiB上限、不跟随重定向；浏览器不代理该接口。
采集失败立即标记不可用，保留上次成功采样时间；15秒资源过期、
120秒数据库统计过期。网站鉴权仍按原接口执行，浏览器增加不会增加统计采集查询。
网站请求鉴权、SSE每帧会话复核和按需历史读取仍查询数据库；
这里不宣称所有HTTP相关SQL的总次数恒定。

资源页沿用 ECharts，切换 API/热群引擎，CPU与内存独立刻度，
容器内存/RSS/Go堆分别展示。总解码P95继续合并原始1000条/24小时有效观测。
旧环境历史不绘图，旧Simon事件显示已停用，不产生虚假“解除”。
045迁移只前向扩展事件组件 CHECK；不修改已应用迁移、原费用或消息格式。
CodecVersion=7和两项readiness保持运行基线状态。
