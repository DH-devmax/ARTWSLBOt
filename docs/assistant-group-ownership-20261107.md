# 助手选群与群归属校验

## 规则

“机器人已在群中”“存在有效群绑定”和“客户已证明群归属”是不同状态。
普通客户只有在群归属有效、本人被分配该群时，才能在助手中选择和操作。
撤权或归属暂停后，旧会话、历史、建议及迟到结果继续重新检查访问权限。

超管可以查询客户有效绑定及自己的演示空间。未认领群明确显示只读，配置建议、
动作建议、确认、功能弹窗保存和旧完整配置 PATCH 均不能绕过归属检查。

超管可通过现有测试认领流程，核验当前机器人原生群主或管理员身份，取得本人
10分钟测试权限。测试认领绑定网站用户、平台、账号、群、账号及绑定版本；
不把客户群标为已认领，不赋予其他用户权限，也不启动自动群管或热群。
到期、解除、撤权、换绑及版本变化后重新校验。本人成功保存配置时仍提升绑定
版本和epoch，使旧计划失效；同一事务取消原测试认领，按原身份、原生证据及
原到期时间创建新版本的后继。它只允许在最初10分钟内继续本人修改，不续期，
不承接他人修改或已经失效的证明。旧记录保持不可变并保留审计关联。

解除时必须使用当前认领。旧编号已有后继时返回状态变化，刷新后解除当前记录，
不会把旧记录的“已取消”误报为当前资格已经解除。创建、配置保存和撤销使用同一
生命周期锁；原生权限变化会撤销等待中及当前有效记录。

测试认领不替代原生动作的来源准入、当前角色、持久预算、期限、幂等和频控。
群管助手不能使用超管受控测试授权或 `native_debug`。

配置审批与原生执行的证据分别核对。审批发现原生角色记录超过60秒时，在通过
本人审批权限及当前计划检查后，释放事务并补读一次所选群角色；最长8秒，
不持锁等待原生接口。重新进入确认事务后，5秒内的新证据必须匹配账号版本、
epoch、连接所有者、部署、群和原生身份，不能覆盖较新的持久角色或群主证明。
角色变化、撤权、策略关闭、换绑或迟到结果均阻断原计划；没有自动重读、续期、
模型调用或原生变更。已提交配置仅核对原执行。

## 实现

控制层统一投影 `group_access`，包含 `ownership_state`、`access_mode`、
`blocked_reason`。助手目录、当前上下文、模块可用性及功能读取复用这份结果。
私有归属记录由控制层查询，客户范围和成员分群显式约束，不扩大租户数据库角色。

配置提交在原版本化事务中锁定并检查归属。助手确认、单功能保存和旧 PATCH
共享同一入口；没有增加另一套执行账本、权限替身、迁移或生产服务。
历史及只读查询不会创建测试认领，也不会续期。前端按服务端原到期时间提前3秒
恢复只读并关闭确认入口；工具查询发现只读时立即同步状态，回合结束再读取最新
上下文。失效后不保持轮询，不为每个群建立采集任务。

## 验证边界

自动回归仅使用合成消息、身份和严格隔离的 `wsl_test`。覆盖两平台、未认领、
正式认领、个人测试认领、他人认领、过期、撤权和版本变化，并检查被拒绝请求
不会改变配置、epoch、审计或创建原生操作。浏览器覆盖四种视口和迟到响应。

真实测试群通过现有网站流程独立核验。开关的保存、运行和原生实际效果分别
记录，不能用合成测试或部署成功替代。本轮实测、交付及待验收项以
[测试报告](test-report.md)和[项目检查点](project-checkpoint.md)为准。
