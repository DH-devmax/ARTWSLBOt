# 客户接入与权限分控

## 超管隔离接入验收

超管在现有受控测试页创建接入范围，选择同平台接收机器人、不同的已认证
自有申请账号、唯一隔离群及默认最长6小时期限，可随时手动关闭。两个账号均须开启受控测试；
范围不要求预先绑定。普通用户流程不变，仍拒绝号池账号作为客户身份证据。

正常向导仅在显式携带有效 `controlled_scope_id` 时进入测试分支，服务端固定
本人演示空间、双方账号和群。好友核对、单条同意、独立私聊和群内证明、
本人确认及必要的转移审核仍逐步执行。有效受控范围内的接入创建与单条好友处理免滑块，
好友同意或拒绝仍须本人明确确认；普通客户及未选择受控范围的超管接入保留滑块。
好友审批及接受邀请仍受频控、一次提交和未知结果核对约束，不凭昵称或
创建范围即完成认领。

每次挑战仍为10分钟。到期显示红色过期状态并禁用提交，无需刷新；
服务端在提交时独立判断。测试归属记录为 `controlled_test`，不用于普通客户
正式验收。关闭或到期后保留配置和历史、暂停绑定及业务，重新开启需新范围
和重新证明；不自动删好友、退群或转回旧租户。

迁移既有测试群时继续核验真实群主并执行版本化转移审核。旧配置密封归档，
旧租户历史正文和财务记录留在原归属，新绑定业务默认关闭。
详见 [受控接入范围](controlled-onboarding.md)。

更新：2026-11-10。本文描述本轮实现的接口和约束。部署、真实平台效果和
灰度开放分别以 [测试报告](test-report.md) 为准。

## 接入流程

### 好友申请核对诊断

申请查找只说明机器人本次返回的有界列表，不等同于官方 App 的全部状态。
未匹配时分别提示“没有本次待处理申请”“同昵称记录已处理”及“申请时间不在范围”；
仍保留同名歧义、时间缺失和列表不完整的独立阻塞。已同意、已拒绝、已删除或
已过期的历史记录不能证明当前好友关系，也不能形成私聊身份或群归属证明。
已有好友应先在官方 App 核对关系，再选择独立私聊核验；不是好友则在新的有效
接入窗口内重新申请，不自动搜索、翻页、重发或审批。

已选中过期申请但尚未提交时，页面明确显示“尚未提交拒绝”，不显示成结果未知。
这条记录已固定为旧申请处理，切换到私聊不展示无法使用的核验内容。
本人可保留并确认处理原申请；若确认已是好友，应先取消本次接入，再明确点击
“重新开始核验”，创建独立的新记录并选择私聊。取消不会拒绝申请或删除好友，
刷新、切换和恢复草稿不会提交或创建新记录。已经提交而结果不明时，继续只核对
原操作，不能取消或重新开始来绕过未决结果。

以下是客户自助接入流程。超管测试已有群不需要注册客户账号、登录客户或开通套餐，
可在用户中心使用独立[测试认领](operator-demo-workspaces.md#超管测试认领)；
该结果不计作客户真人挑战通过。
新增群也从用户中心的接入向导开始，不跳转后台。客户负责人只能接入自己的群；
超管默认使用自己的私有演示空间，也可明确选择已有真实客户代为接入。演示模式来自网站
会话并持久保存，不由浏览器指定；不创建虚构客户、套餐或订单。

普通接入创建、本人确认同意单条好友申请及旧授权申请要求网站滑块一次性验证，
不改变下述好友、群归属和本人确认流程。验证及实际发布记录见
[网站滑块验证](website-captcha.md)；进度读取、取消与关闭不提交原生操作。

1. 超管在管理后台创建负责人邀请。链接令牌只返回一次，数据库仅存摘要，
   默认24小时有效。新用户设置自己的密码；邀请已存在的网站账号时，
   必须由该账号登录后接受。网站激活不会注册或登录原生账号。
2. 负责人选择旺商聊或辣椒聊。控制层从该平台、管理用途、已认证且连接
   新鲜的号池中分配机器人，同时预留容量。向导显示平台、原生昵称及可复制的
   对外添加账号，不使用内部UID替代搜索账号。
3. 两平台统一由用户在官方 App 添加机器人。创建挑战后发送申请，填写本人当前
   原生昵称，再点击查找本次申请；时间范围由服务端限制在本次10分钟挑战内，
   不读取或依赖好友申请附言。只从有界待处理窗口选择收件机器人、方向、昵称和
   申请时间均相符的唯一申请；同名多条、字段缺失或无法分类的窗口外申请不提交，不自动翻页扫描。
   页面展示这一条的昵称及申请时间，本人确认并完成一次滑块后最多同意一次。
   昵称和时间只是联系人定位条件，不构成身份、群权限或业务启用证明。
   之后仍须向机器人发送网页给出的独立私聊核验内容；已选择申请时只接受同一
   原生发送者的私聊和群内证明。已是好友或机器人不要求审批时，直接走私聊核验；
   机器人已在群时仍可直接完成群内挑战。核验内容仅在首次创建时签发；
   关闭后重新打开若未保留，页面提示取消并重新开始，不伪造恢复内容。
   旧入站附言核验、普通用户搜索及主动申请入口停止新提交；旧审批和主动申请
   历史继续可查，未知结果仅核对原记录。页面读取、刷新和切换步骤不触发原生读取或审批。
   手机搜索认证和原生搜索／主动申请底座保留，仅供超管持久受控授权调试；
   用户接入不依赖手机搜索会话，助手和热群没有这些工具。
4. 需要机器人接受群邀请时，指定同一已证明账号发来的唯一群邀请。
   控制层核对邀请人、接收机器人和群，本人确认后独立持久操作最多提交一次。
   结果不明只查询原操作，好友通过本身不能创建群归属或启用业务。
5. 机器人入群后，申请人在目标群发送独立挑战码。证据来自已认证并持久
   保存的接收消息，浏览器填写的群和原生身份只用于查找。
6. 新鲜成员名册证明申请人为群主时，可以本人确认绑定；原生管理员申请
   进入超管审核。页面显示实际群、平台和机器人，不能凭同名群自动确认。
7. 新绑定、恢复绑定或补核验旧绑定保留已有配置，关闭运行。负责人核对套餐、超管开通
   上限和成员权限后，逐群确认启用。页面读取与关闭弹窗不会提交。

挑战有效期10分钟，私聊和群内验证码相互独立，绑定网站用户、空间、平台、机器人及版本。
页面按有效期自动显示红色感叹号和“已过期，请重新开始核验”，收起失效内容与旧提交
入口，无需刷新；从后台切回页面时也会重新检查时间。本人点击“重新开始核验”后，
保留原平台和所属空间，重新完成正常滑块并创建新挑战；不会自动续期或提交。
若已有好友或入群操作结果未知，先使用原记录核对入口，确认后才能重新开始。

显式核对时若没有本次有效申请，但发现同昵称、同收件机器人的唯一旧待处理申请，
且其原生时间至少早于本次挑战开始10分钟，默认按“拒绝旧申请”处理。
页面提示该申请已过期并进入一次滑块确认，取消滑块后可点击“处理过期申请”继续；
正常新申请优先，不会走拒绝。原生已过期或已处理记录不再重复拒绝。
确认提交只使用密封的原申请，不接收客户端指定目标。成功后结束旧核验并提示
“旧申请已拒绝，请重新开始核验，并在官方 App 重新申请添加机器人”。
未知结果只能核对原记录；打开页面、刷新、恢复和计时过期均不触发拒绝。

绑定成功与待平台审核不会仅因挑战原截止时间已过而改成过期。
联系人确认使用密封的单条申请记录，不伪造成接收消息事件，不写入身份核验字段。
确认过目标后，私聊和群内证明只接受该原生账号。昵称、账号和附言不进入日志或审计正文。
取消和到期不删除已建立的好友关系，也不自动删除好友制造验收样本。
所有者在2026-11-09本轮明确授权临时删除测试关系时，超管可另建独立的单账号、
单目标、一次预算 `friend_delete` 受控窗口并人工确认；这不是客户接入步骤，
不会让取消、过期、重试或后台任务触发删除，也不自动重加好友。
删除的双平台契约和待验边界见[账号好友受控操作](native-social.md)。
两平台分别读取自己的申请标识和时间契约，不把旺商聊数字 ID、nonce 套入辣椒聊。
申请状态核对只读取原操作和同一申请，不以仅有好友关系认定一次审批成功。
结果未知时，只有精确匹配原申请标识、双方身份、昵称和原生申请时间的成功或拒绝状态
才能收敛为终态；缺失或仍在待处理不会自动重发。
单账号变更至少间隔5秒，申请人每小时最多3次、机器人每小时最多12次，
不提供批量审批或自动重试。未提交的准备记录在重启后失效；已开始提交的记录转为未知，
必须核对原结果。自然过期会释放尚未提交的准备记录与容量预留，不需要靠重启清理；
已经提交且结果未知仍保留占位。确认前重新读取原申请和当前连接，不把选择联系人时的
旧采样时间当作本人必须立即确认的限制。取消或过期不会删除已建立的好友关系。
群归属证明和好友／私聊邀请证明互相独立。邀请指纹只表示
当次已读取的邀请，不表示第三方承诺了某个过期时间；提交前仍重新读取。
旧人工认领不会自动变成消息核验通过。跨租户转移必须经过超管审核。

## 用户中心入口

工作台“接入新群组／绑定群组”和空列表“接入第一个群组”打开作用域弹窗。
按分配机器人、添加机器人、确认单条申请、私聊核验、邀请入群、群内证明、确认绑定展示进度。打开和关闭弹窗只读数据，
明确点击“开始核验”才分配机器人并预留容量；邀请接受与最终绑定分别本人确认。
绑定成功仍关闭业务运行，不能将“已保存”当作“运行中”。

超管默认使用“我的演示空间”；代客户接入时选择真实已有客户，选择列表有界分页和搜索。
机器人容量、连接、epoch、版本、消息挑战、原生角色、期限、幂等及邀请准入
继续验证，商业套餐限制只对超管本人的接入步骤豁免。后续客户与自动任务仍使用
该客户自己的套餐、能力和钱包；超管本人空间后台任务使用独立平台空间计费。
确认弹窗显示服务端返回的所属空间、平台、
群和机器人，已有绑定及跨客户转移继续遵循原规则。

## 开通与灰度顺序

| 顺序 | 操作人和入口 | 完成条件 |
| --- | --- | --- |
| 1 | 超管：管理后台创建负责人邀请 | 客户本人激活或登录后接受；不共用超管账号 |
| 2 | 超管：套餐与积分、客户权限上限 | 套餐包含对应平台和模块；需要助手时使用PRO，逐项开通权限上限 |
| 3 | 客户负责人：接入群组 | 按分配机器人完成挑战；群主本人确认，管理员申请等待审核 |
| 4 | 超管：对应平台、动作和来源的准入 | 核对证据后先指定测试群灰度；助手、自动群管、接入和热群分别设置 |
| 5 | 客户负责人：成员权限 | 分配具体群和字段；群管确认模板还需单独选择允许的原生动作 |
| 6 | 获授权用户：群功能 | 保存拦截词、黑名单、豁免和关键词回复；保存不自动启用运行 |
| 7 | 客户负责人：运行与权限 | 核对阻塞原因，按当前版本显式启用本群业务 |
| 8 | 测试参与者：指定测试群 | 低频逐项确认实际效果，核对原操作记录后再决定扩大灰度 |

迁移不会替旧绑定补造身份挑战证据。需要重新核验时，由客户负责人完成接入
证明；不能直接使用号池机器人身份代替客户。原生“普通成员”与“号池用途”是
两个不同维度：号池账号即使不是群管理员，也不能充当客户申请人。普通成员本身
没有认领资格；客户申请人必须是本人可控制的非号池群主或管理员。
PLUS不包含助手能力；PRO仍须满足权限、有效群绑定和积分条件。超管演示权益
不替客户开通套餐；演示业务的权益与计费见[工作区与演示权益](operator-demo-workspaces.md)。

已有绑定缺少归属证明或证明已暂停时，客户负责人从对应群的“重新核验”进入，
请求携带该群及当前绑定版本，继续使用原机器人。创建、查看或取消挑战不会改变
原绑定、配置或运行状态；取得新的认证消息证明并本人确认／平台审核后，才保存
归属证明、提升绑定版本和epoch、关闭运行。已验证且有效的绑定不能借此重复改绑；
跨客户或版本冲突仍拒绝。旧人工审核不能替代这次认证消息证明。

核验进度分别提示号池身份、非群主／管理员、私聊与群内身份不同等固定原因。
上游读取失败只记录安全分类；不保存上游正文。每条挑战消息最多读取一次原生角色，
刷新进度不会重试，也不触发账期刷新、发放积分或更新绑定版本；
需要重新核验时由本人重新发送同一有效挑战内容。

操作记录按页面操作、群管助手、自动群管、群接入和热群区分来源。结果不明时，
查询原记录或执行核对，不点击新建操作重发。停用本群会阻止未提交的业务任务；
已经提交的原生效果仍需按原操作核对。

## 权限

有效权限同时受到平台正式准入、套餐、超管能力上限、租户授权、成员群范围、
字段权限、群运行状态和当前原生角色限制。

| 身份 | 能操作的范围 |
| --- | --- |
| 超管 | 后台维护能力上限和正式准入；用户中心使用同一助手及独立演示权益，保留本人对话 |
| 客户负责人 | 本租户成员与角色、分群和逐动作授权、群运行开关及绑定撤销 |
| 客户成员 | 明确分配的群，以及获准的字段、建议和本人确认动作 |

负责人不能开通超过超管上限的能力，也不能修改号池全局资料、模型供应商、
密钥或平台正式准入。旧 `members:manage` 委派不再授予成员管理权。
“群管本人确认”模板只授予建议和确认流程；踢人、全群禁言等动作单独选择。

PLUS不包含群管助手。PRO助手与热群使用现有共享积分，720小时账期保持不变。
超管本人演示AI由平台承担实际费用并计入平台总预算，不扣客户积分；客户
本人和自动业务继续使用客户套餐。所有真实原生动作仍检查有效绑定、归属、
当前角色和对应来源准入。受控测试不能替代正式业务条件。

## 接口

所有已登录接口使用现有网站会话、CSRF及平台视图；群ID不能充当授权。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/customer-invitations` | 超管创建网站邀请 |
| `POST /api/v1/customer-invitations/preview` | 有界预览令牌对应的邀请，不返回其他账号信息 |
| `POST /api/v1/customer-invitations/activate` | 新网站用户激活 |
| `POST /api/v1/customer-invitations/accept` | 已登录网站账号接受指定邀请 |
| `POST /api/v1/customer-invitations/{id}/revoke` | 超管撤销未使用邀请 |
| `GET /api/v1/group-binding/context` | 超管读取有界客户选择；客户负责人只读取自身范围 |
| `POST /api/v1/group-binding/challenges` | 创建当前平台接入证明及容量预留 |
| `GET /api/v1/group-binding/challenges/{id}` | 仅查询持久进度，不调用上游 |
| `GET /api/v1/group-binding/challenges/{id}/friend-verify` | 仅查询好友核验持久状态 |
| `POST /api/v1/group-binding/challenges/{id}/friend-verify` | 旧入站核验入口已停用；不提交审批 |
| `POST /api/v1/group-binding/challenges/{id}/friend-candidate` | 按本人昵称和服务端挑战时间选定唯一待处理申请；不审批 |
| `POST /api/v1/group-binding/challenges/{id}/friend-approve` | 本人确认及一次性滑块后，同意已密封固定的单条申请；不证明身份 |
| `POST /api/v1/group-binding/challenges/{id}/friend-attempts/{operation}/reconcile` | 只核对原好友审批结果 |
| `POST /api/v1/group-binding/challenges/{id}/friend-reject` | 滑块后单次拒绝密封的超时旧申请；成功后要求重新申请 |
| `POST /api/v1/group-binding/challenges/{id}/friend-target` | 普通接入已停用，返回410；原生能力仅保留受控测试 |
| `POST /api/v1/group-binding/challenges/{id}/friend-send` | 普通接入已停用，返回410；不发送 |

| `POST /api/v1/test-tools/onboarding-friend/challenges/{id}/friend-send` | 仅在匹配的受控窗口内单次申请；客户接入不使用 |

| `POST /api/v1/group-binding/challenges/{id}/invitation-accept` | 本人确认接受已核验邀请 |

写操作使用返回的当前版本；可重试提交另带原幂等键。密封计划、未知结果和
历史审计保持原编号，不能通过新建任务绕开。
超管创建挑战时默认使用自己的空间，代客户接入才提交 `target_tenant_id`；
普通客户不能借此指定其他客户或演示空间。
返回的`mode`和`customer`来自服务端，确认和后续提交继续使用记录中的固定归属。

普通审核不能批准跨租户转移。专用转移审核要求申请人当前为原生群主，
明确核对原租户及绑定版本。转移前归档密封配置并取消待执行工作，清空
新租户设置、聊天偏好与成员分群，关闭运行并提升版本和epoch；旧租户
对话、活动及台账仍归旧租户。未解决的已提交操作会阻止转移。

## 运行和恢复

正式准入为关闭、指定群灰度或开放，按平台、动作、来源独立保存。接入、
助手、自动规则和热群互不继承。受控测试仍是独立超管入口。

群主变化、机器人离群、绑定撤销、套餐到期、成员撤权及版本变化会阻止旧任务
继续提交。已提交的结果不明任务保留查询，不能自动重试。恢复已撤销绑定
必须重新证明、检查容量并提升版本和epoch。

邀请、证明、规则任务不向助手注册管理工具，不增加接收器或每群常驻任务。
验证码、密码、挑战正文、模型提示词和原生凭据不进入操作记录和超管审计。

## 机器人添加信息与好友准入

`robot.native_id` 是内部原生身份，`robot.add_account` 才是对外添加账号。
旺商聊从密封登录会话的 `session.account_id` 读取；辣椒聊从密封会话的 `user_id`
读取，并通过认证基本资料同步昵称。读取失败时返回 `add_available=false` 和安全原因，
不猜测、不把内部UID替代搜索号，也不新增手工映射。

新的联系人单条同意复用 `group_binding_friend_gates`，按平台和机器人独立准入，
初始关闭；既有好友的私聊核验不依赖此准入。选定申请及最终提交均检查同一准入版本，
并核对账号版本、epoch、接收所有者、凭据摘要和申请原生标识；读取失败不批准。
旧 `group_binding_outbound_gates` 不再授权客户搜索或主动申请，只保留历史兼容。
原生搜索和主动申请另须超管受控测试的显式持久范围与预算，不由普通接入挑战授权。
已应用迁移不变，063前向扩展新的 `incoming_contact` 流程；旧挑战继续其历史查询，
不会自动转为新流程或把旧审批当成身份。回滚旧API后，新流程不能被旧入口提交。
管理后台在管理用途机器人的账号工作台提供“好友接入准入”弹窗，显示当前保存状态、
平台、机器人及证据引用。打开、读取和关闭不修改准入；显式保存使用当前版本，
客户、聊天用途账号和群管助手不获得此维护权限。
未完成真实灰度验收的入口保持关闭；普通人工审批、助手、热群和群邀请准入不继承此权限。
每账号变更串行且至少间隔5秒；一个挑战固定一个目标、最多一次同意。
排队和新鲜读取完成后才预留写入冷却，不占用接收与 ACK 路径。
已发出请求的未知结果只核对原操作。原申请有明确拒绝证据时可结束为失败；
提交期限及最终栅栏时限均已结束的残留 `submitting` 可在线核对，不要求重启。
好友关系不代替网站身份或群归属证明；已是好友及旧挑战继续使用独立私聊／群内证明。
