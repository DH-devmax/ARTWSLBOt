## 当前能力与限制

- 已实现：账号/手机号密码登录、短信登录、换设备短信校验、六位安全码、官方人机验证 SDK。
- 已实现：桌面 2.8.3 的签名、sealed box、原始 8 字节 nonce AEAD 和响应绑定校验；独立手机搜索适配固定为 Android 3.7.4，不能复用桌面会话。
- 已实现：取得并加密保存原生业务与 IM 凭据；不保存登录密码、验证码或人机验证结果。
- 已实现：超管权限、CSRF、账号/发起人绑定的 10 分钟事务、账号版本与部署版本校验、当前网站会话复核。
- 已实现：新账号开户专用短信、昵称及密码、协议确认、开户提交前持久屏障、显示账号 ID 后显式登录。
- 离线配置工具分别读取固定桌面和 Android 安装包；手机配置使用独立入口导入，不能覆盖桌面配置。
- 已实测：固定官方 macOS 2.8.3 配置导入后，真实匿名 `get-sys-cfg` 请求返回成功；它不包含登录、短信或开户。
- 未验收：真实桌面账号登录、官方验证码联网流程、真实手机号验证码及设备挑战。
- 接收专用会话恢复、IM 换票和 NIM 长连接见 `docs/native-receiver.md`，真实兼容验收仍未通过。
  已注册不代表已登录，已登录不代表在线收消息。

**用户要求的注册指旺商聊新账号开户，不是网站自助注册，也不是新增账号面板。**
旧适配器 `registration.py` 只有接入事务，不包含开户。2026-10-25 已从用户提供的官网取得
Android 3.7.4 安装包，核实独立开户路由、短信用途、字段及成功后跳转登录行为，
来源、签名、哈希和证据见 [官方客户端核验](official-client-research.md)。
已替换原 `native_signup_contract_missing` 占位接口。原 3.7.4 移动实现现已删除，
保留的低层密码学样本不是移动登录适配器。桌面注册、真实账号与线上响应仍须
独立验收，不把离线一致或注册成功解释为已登录。

## 使用方式

1. 按 `docs/docker-operations.md` 使用标准 Docker Compose 构建与迁移，不运行宿主机 API。
2. 网站超管选择旺商聊或 MaiBot 工作台；顶部「机器人连接状态」内的「协议配置」可导入经过核实的协议 JSON。
3. 点击顶部「注册 / 登录」，填写机器人名称，在统一弹窗内选择「原生登录」TAB。
   首次提交有效表单才创建当前工作台的面板；已有机器人从状态表或顶部连接状态打开，不重复创建。
   多账号分别保留各自验证事务，切换查看不提交原生登录。
4. 选择密码或短信方式，人工完成官方人机验证；按平台实际要求补充短信或安全码。
5. 状态为「已登录，会话已加密保存」才表示凭据持久化完成。连接状态仍是「未连接」。
6. 关闭面板只清理表单并停止该面板轮询；「取消验证」会使事务失效。重开可继续同一未过期事务。
7. 「清除会话」擦除本地保存的凭据，但保留原生 UID 与历史关联，防止换号串用历史业务。

注册与登录不再使用两个入口争抢同一账号。同一超管切换 TAB 时，服务端原子替换空闲事务并立即作废旧 ID；
切换不会发短信或提交原生认证，也不重置尝试次数、冷却时间和原验证期限。
正在执行或上游结果未知时禁止直接切换；另一位超管仍不能接管未过期事务。
关闭再打开弹窗可恢复本组件保存的未过期事务和 TAB，但不会保留密码、短信码或手机号输入。
刷新整个页面后，自己的空闲旧流程也能被新流程替换，不再误报为“另一位超管登录”。
开户已经提交但结果待复核的持久化屏障不随切换、关闭或服务重启清除。

### 开户

1. 选择对应工作台，点击顶部「注册 / 登录」，填写机器人名称。打开或切换 TAB 不会创建原生账号或空面板。
2. 切换「新账号注册」TAB；也可从已有空面板的状态行打开。
   已绑定身份、已注册或开户待复核的面板禁用注册 TAB；未导入协议配置时只显示阻塞原因。
3. 填手机号，确认已阅读旺商聊协议、隐私政策并具有手机号使用权，人工完成人机验证后发注册短信。
4. 输入短信验证码及 6–16 位混合密码，再次人工验证后提交。
5. 成功后显示的是旺商聊 `accountId`，不是 `native_uid`；点击「登录新账号」显式进入登录。
   登录返回的 accountId 必须与已注册身份一致，才能保存原生 UID 和凭据。

两套工作台的账号池和验证句柄分开。现有面板默认归旺商聊，不自动复制到 MaiBot；
同一原生身份不能绕过全平台唯一绑定而同时登录到两个面板。工作台或账号面板切换不发送登录、断线或配置修改。

开户不会自动调用登录、自动设置安全码、打开消息连接或发群消息。网站账号仍由超管创建。
手机号、密码、短信验证码及人机结果不写入开户记录。当前桌面注册步骤不提交原生昵称；
网站机器人名称仅为备注，不是设置原生昵称。密码采用官方字符集合与混合规则，
并额外拒绝纯空白和控制字符。

不要在聊天、浏览器控制台、截图、版本库或日志里粘贴协议密钥。配置上传使用原始 JSON 字符串，
不在浏览器中把 metadata 的 uint64 解析成 JavaScript 浮点数。

## 部署配置契约

| 字段 | 约束 |
| --- | --- |
| `origin` | 已核验的 HTTPS origin，不能带路径、用户凭据、查询或片段 |
| `headers` | 只使用小写 `accept`、`content-type`；桌面 `x-version/x-device/x-client` 由服务端固定，导入内容不能覆盖 |
| `metadata` | 14 个无符号整数，保留原始整数精度；不要使用浮点序列化工具 |
| `signing_seed` | 标准 Base64，解码后 32 字节 Ed25519 seed |
| `body_key` | 标准 Base64，解码后 32 字节业务请求密钥 |
| `server_key` | 标准 Base64，解码后 32 字节服务端 Curve25519 公钥 |
| `message_key` | 可选，32 字节密钥，登录阶段不使用 |
| `captcha_id` | 原生部署对应的官方人机验证站点 ID |
| `device_id` | 原生部署设备标识，用于获取 IM 凭据 |
| `app_key` | 可选，预留 IM 部署标识；登录阶段不使用 |
| `protocol_version` | 必填，唯一允许值 `2.8.3`；空值、移动协议和其他版本全部拒绝 |
| `desktop_platform` | `macos` 或 `windows`；省略时兼容旧 PC Windows 配置；分别固定 `X-Client=10/11`，均为 `X-Device=1` |

配置不能从网站查询接口导出明文，只返回 origin、协议版本、版本号和加密构建可用状态。
配置替换会使已保存会话标记为需要重新登录，并取消内存中的登录事务。
配置与会话分别使用 AES-GCM 及不同 AAD 绑定保存，主密钥仍来自服务端受控环境。
租户数据库角色不能读取部署表及账号凭据列。
出站只访问 HTTPS；拒绝重定向和环境代理；DNS 全部候选地址需通过公网检查，连接实际拨已检查 IP。

### 注册短信的有界原因诊断（2026-11-01）

`1001`为固定官方共享API的通用业务码，不能解释为桌面客户端传输解析码或号段准入。
已核验码表来源与桌面适用边界见`official-client-research.md` E42/E43；并非所有码均已
在现行注册短信接口实测。认证路由和`VERIFY_FOR_REGISTER`用途共同约束分类；
只有明确业务码或精确匹配的安全短语才提示频控、已注册、安全验证、号码或号段限制。

拒绝时先保留有效业务码，再检查原因；对象、数组等非文本原因不会抹掉业务码。
空/缺失/null原因、未识别文本、非文本原因、超过512字节原因分别产生固定诊断枚举。
只对白名单短语做有界JSON字符串解码，不返回、审计或持久化上游原文或其中身份/票据；
无论原因结构如何，成功响应仍须满足原有字段类型校验。
`diagnostic_version=2`标识本次失败实际使用的分类版本，重新手动提交时清除旧结果；
`GET /native-deployment`的`auth_diagnostic_version`仅说明当前服务支持的版本，
不代表发生过真实短信请求。旧结果缺少分类时，页面明确标记无法判断原因是否为空。
轮询、关闭、刷新及诊断查看都不会自动重发短信，未知结果保持原复核屏障。

本轮仅授权合成回归，真实注册短信、注册及原生登录没有验收；下一次发码须由用户手动操作。
历史未保留的原因无法还原，不能据此断言特定手机号或号段被禁止。

### 关闭事务后的诊断核查（2026-11-01）

认证事务仅在内存中保留十分钟，原始上游原因始终不保存。此前关闭面板或事务过期后，
安全原因分类也随事务丢失；访问日志中的HTTP202/200只能证明提交/轮询完成，
不能恢复业务拒绝原因或证明短信已发出。

本轮补充`native_auth_rejected`安全审计：控制层绑定发起网站用户、本站账号，
正文仅含用途、阶段、白名单错误码、已核验数字业务码、原因分类和诊断版本。
不含认证事务句柄、手机号、验证码、人机票据、密码、原生身份或上游原文。
无法识别的数字不写入审计。沿用现有超管审计查询及租户隔离，不增加数据库迁移。

记录在原生请求完成后、管理器锁外执行，上限四秒；失败仅输出固定持久化告警，
不重发原生请求、不延长验证期限、不改变未知结果屏障或登录/注册状态。
每次失败最多一条，轮询不写入；删除账号后到达的记录不会重建该账号审计。
这是尽力保存的排查信息，不是原生提交的持久事务保证；进程崩溃或记录失败仍可能缺失。
不能补录本轮之前已经丢失的分类，更不能把诊断留存修复当成真实注册短信验收通过。

### 密码登录拒绝诊断

`-1`与`1001`都是业务响应码，不能仅凭数字认定密码错误、验证码失败或登录协议不可用。
此前所有未识别的`-1`都会落到笼统的“旺商聊未接受此操作”，且页面无法区分
密码验证、换设备验证、消息凭据获取与本地保存阶段。2026-10-28候选修正按操作
保留拒绝类别，并通过`failure_stage`返回固定阶段码；不返回或保存密码、手机号、
验证码、票据及原始上游文案。

密码字段对照固定桌面`Login-723afdcb.js`：`account`、`passwd`、
`validateStr`、`type`；11位数字手机号使用`LOGIN_TYPE_PHONE_PWD`，
原生账号使用`LOGIN_TYPE_ACCOUNT_PWD`。不额外散列或修改密码，也不改用移动端。
仅在上游原文精确匹配已知密码错误短语时显示“账号或密码不正确”，其中包括
桌面源码中的`账号或密码错误，请重新输入`和`账号或密码错误, 请重新输入`。
其他文案一律不反射；不从`-1`猜测原因，不自动重试或转短信。

`failure_stage=password_login`表示密码登录步骤拒绝；
`device_verification`表示设备校验；`im_credentials`表示身份验证后取得消息凭据失败；
`session_save`表示上游凭据已取得但本地保存未完成。短信、安全码和注册各有独立阶段。
每次显式提交会清除旧阶段及返回码，事务仍绑定原网站用户和账号。
未知网络结果仍进入`unknown`，不会因为诊断优化而成为可重试的已知失败。

旧版已完成的失败没有保存原始原因，不能从这次页面的`-1`补推根因。
此候选须经部署后由用户人工提交新的登录，才能确认真实拒绝阶段；
合成测试通过不代表上游已接受密码登录。当前运行版本及实际结果以
`docs/test-report.md`为准。

### 从移动端迁移

迁移 014 停用已启用接收，提升接收 revision；已有凭据的账号提升 epoch/version，
标记 `reauth_required` 并关闭原生动作。它不删除账号、原生身份、群授权、事件、
财务证据或未知开户屏障，也不将旧票据改标为桌面票据。旧凭据保留加密状态，
但恢复客户端和消息连接都会拒绝非桌面协议。

旧移动配置的 `GET /native-deployment` 返回
`configured=false, migration_required=true, login_adapter=desktop`，保留原版本号，
不返回旧密钥。导入经过核验的桌面配置必须使用该版本，不用重建数据库或账号。
未配置桌面端时，登录/注册表单不能提交。桌面业务密钥、签名引导和会话必须
来自桌面契约，不能沿用 Android 配置后只替换版本。

`tools/native_client_config.py` 已降为历史 APK 只读检查工具，
`--output` 在读取客户端或创建文件前拒绝。没有新的移动配置生成入口。
`tools/desktop_client_config.py` 从固定桌面主进程、原生可执行文件和配置 JS
独立校验引导签名链，生成全新签名身份及稳定 IM 设备 ID 的 `0600` 私有配置。
它不运行客户端，不从 APK 取密钥，不覆盖已有文件；可选 `--im-sdk/--im-output`
从固定桌面 NIM 初始化代码提取独立 IM 配置。哈希与定位证据见 E21–E25。
导入是受控超管操作，不在镜像中预置私有配置，也不自动替换已有部署。

本机桌面配置版本 2 已经由带 CSRF 的超管 API 导入，真实匿名配置读取成功。
删除的机器人面板没有恢复；之后由用户在顶部填写名称并人工登录。
不同桌面平台的保存会话不能互换，平台变化必须重新取得对应会话。

### 手动配置验证

超管在「协议配置」点击「验证配置」，以当前版本请求
`POST /native-deployment/check`。Go 只允许一次固定匿名
`/v1/settings/get-sys-cfg` 读取，沿用持久化 nonce 分配、严格 TLS 与公网地址检查，
不会提交登录、注册、短信或群动作。单进程串行，间隔至少 30 秒，遵守更长的
上游 Retry-After，不自动重试；20 秒总期限。
响应后再次核对部署版本与超管网站会话，变更则拒绝该结果。
只返回验证标记、验证码是否启用、采样时间及版本，不转发上游完整配置。
通过只说明此匿名业务请求成功，不能开启 `native_ready` 或推断消息已在线。

`tools/android374_oracle.py` 在有界 ARM64 模拟器中执行固定安装包的交换和上下文序列化函数，
只供应内存操作及受控 libsodium 调用，使用合成密钥生成回归样本，不执行 APK 启动流程。
测试向量位于 `internal/nativewire/testdata/android374_exchange.json`。
比较时向原生函数提供与 Go 相同的合法 Zstd raw frame；不声称两种压缩器逐字节相同，
也不以此替代网络、风控或真实验证码验收。

## 接口与状态

接口均位于 `/api/v1`，只允许有效网站超管会话；写入需要 CSRF。

| 接口 | 行为 |
| --- | --- |
| `GET/PUT /native-deployment` | 查询脱敏配置状态 / 使用 `version` 导入配置 |
| `POST /native-deployment/check` | 超管手动、版本化验证唯一匿名配置路由；不自动登录 |
| `POST /accounts/{id}/native-auth` | 使用账号 `version` 开始，返回 `transaction_id`；同一账号同一发起人复用活跃事务 |
| `GET /accounts/{id}/native-auth/{transaction}` | 查询状态，不返回 JWT、IM token 或密码 |
| `POST /accounts/{id}/native-auth/{transaction}` | 执行异步步骤，`202` 后轮询 |
| `DELETE /accounts/{id}/native-auth/{transaction}` | 取消，不代表撤销已被远端处理的登录 |
| `POST /accounts/{id}/forget-session` | 使用 `version` 清除本地凭据 |
| `POST /native-signup` | 使用空面板的 `account_id`、`version` 开始开户事务 |

步骤 `action`：`password`、`sms_request`、`sms_verify`、`sms_resend`、`security_verify`、`retry_finish`。
开户事务只接受 `signup_sms`、`signup_resend`、`signup_submit`，不能混用登录短信或登录步骤；
每次均需 `agreed=true`。最后一步使用 `password`、六位 `code` 和人工 `captcha`，
手机号绑定首次短信请求，最终提交不能通过改写 `account` 换号。
桌面 `phone` 的 `countryCode`、`nationalNumber`、`maskedNationalNumber` 均为字符串，
后者按首次手机号构造；注册短信省略旧大写`Key`，最终注册仅提交`key`、
`verificationCode`、`password`、`validateStr`和原`phone`。旧网页传来的`nickname`
仅作兼容解码，不传给原生接口、不保存，也不表示原生资料已更新。
登录表单的数据只随本次请求提交，不落持久化存储或浏览器 storage。
事务最多 12 次步骤，同一账号 10 分钟最多新建 4 次，全局最多 10 个活跃事务。
短信重发最少 60 秒；验证码验证不受重发冷却阻挡。429 遵守 `Retry-After`，账号请求串行，无自动重试。
所有账号在发送前通过 PostgreSQL 原子持久化分配桌面纳秒请求 ID，保留桌面 nonce 格式，
避免并发账号碰撞、进程重启或时钟回退后重用本平台请求编号。配置替换不清零高水位。
数据库不可用时拒绝发送，不回退到随机编号或绕过持久化。

状态包括 `pending`、`working`、`sms_required`、`security_required`、`security_setup_required`、
`connection_pending`、`authenticated`、`failed`、`unknown`、`cancelled`；
开户增加 `signup_sms_required` 和 `registered`，并在 View 中返回 `purpose=signup`。
过期事务不可继续，前端按截止时间显示过期。
网络断开、5xx 或响应无法核验时显示结果未知，不能在同一事务直接重新发送登录/短信。
需先人工核对官方客户端，再取消并重新开始。

账号版本、部署版本、网站会话在最终凭据提交事务内重新校验；原生 UID 全局唯一，
不能用新身份覆盖已有账号 UID。事务仅存内存，API 重启后失效，已提交的加密凭据仍在数据库。
Go 字符串的内存回收不提供完全擦除保证；不要将进程转储当作可公开诊断附件。

### 不可幂等开户与复核

`007_native_signup.sql` 的 `native_signup_attempts` 由平台角色独占访问。
最终开户发送前，在事务内复核网站会话、部署版本、面板版本与未绑定状态，再提交 `submitted` 记录。
数据库不可用或持久化未成功时不发送开户。平台不会持锁等待上游 HTTP。

有效成功回包只记录 `registered` 和账号 ID；明确上游拒绝记录 `rejected`，允许修正。
断网、坏回包、5xx、无法确定的 HTTP 状态及成功后记录失败保留 `submitted`。
同面板 `submitted/registered` 有数据库唯一屏障，取消、过期、重启、改配置都不解除；
未确认开户还会阻止在该面板直接登录。账号列表显示「开户结果待复核」。
已提交后即使浏览器取消，仍尽力记录可信回包，但不偷偷重新发请求。

首期尚无自助解锁未知开户结果的接口。必须由超管使用官方客户端核对真实结果并保留证据，
再通过受控运维复核，不能直接把 `submitted` 改成成功或删除记录来“重试”。

### 上游1001与错误范围

数值1001不是“执行过登录”的证明。注册、短信、登录分别返回
`native_signup_rejected_unspecified`、`native_sms_rejected_unspecified`、
`native_login_rejected_unspecified`，保留`provider_code=1001`。
2026-11-01补齐按认证路由与SMS用途区分的共享API业务码映射，静态来源及
桌面适用边界见official-client-research.md的E42/E43，不能将客户端传输层
1001当成业务码。注册短信1037映射已注册；登录/换绑短信不复用该注册提示。
1038/1043明确频控分别增加本地至少60/30秒冷却，不自动重试，也不声称这个
本地时长等于上游解除限制时间。1040为人机/行为安全验证拒绝，与六位安全码不同；
1000/1002、1036/1044、1200/1201分别保留参数、验证码、版本及IP原因。

仅把至多512字节内规范化后的精确白名单词映射成安全原因码；号段/号码限制
必须收到明确对应文案，1001本身永远不映射该限制。额外文字、号码、票据或
HTML不作模糊匹配。诊断只返回provider_code_classified、
provider_reason_classified、provider_reason_empty或provider_reason_unrecognized，
后两项明确区分“上游文本为空”和“有文本但尚未安全识别”；旧无诊断记录不倒推。
Manager对诊断再次白名单过滤，不返回、记录或持久化任意上游msg，不能把
主动过滤的信息误称为“上游未提供原因”。无法核验的原因不猜测为密码、
验证码、已注册或号段限制。
读取结果或界面轮询不会自动重试注册/短信。明确业务拒绝仍记为rejected，
未知提交仍保持原有持久屏障。修正提示与参数不等于真实开户已通过。

## 验证范围

离线 HTTP 服务只使用合成域名、密钥、验证码与凭据，覆盖唯一桌面协议的请求签名、
响应绑定、安全码、JWT 轮换、IM 凭据及 429 不重试。另验证移动版本、空版本、
移动身份字段以及旧移动会话均被拒绝。PostgreSQL 集成测试只重建 `wsl_test`，
覆盖权限、加密、重复 UID、配置变化、账号变化、网站退出和取消，
并验证旧配置迁移状态、桌面显式导入和迁移后的接收栅栏。它们不替代真实平台验收。
开户补充覆盖专用短信用途、字段名、人工确认、手机绑定、密码规则、不自动登录、
提交前落盘、已注册身份核对、明确拒绝后修正、未知结果跨重启拦截及取消后保留可信结果。
低层 `nativewire` 保留历史 3.7.4 官方交换/上下文固定样本，不再提供对应认证客户端；
历史密码构件向量不能作为移动端接入入口，亦不证明桌面开户兼容。

真实验收需要已核验协议配置、受控测试账号及人工验证码。不得将正式账号凭据写进测试 fixture，
也不得因认证通过而自动开启接入、群操作或 AI。
