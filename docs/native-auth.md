# 原生登录接入

截至 2026-10-25，开户与身份认证增量不启动 NIM 长连接、不发群消息，也不开放原生管理动作。
2026-10-26 新增独立的接收专用链路，边界及真实联调状态见 `docs/native-receiver.md`。
登录实现参照锁定的 AstrBot `a672ef93cb7dbfb854ae01ff131267b9e8a1e050`；
开户契约来自用户提供官网的 Android 3.7.4 客户端静态核验，不是从接口名称推测。

## 当前能力与限制

- 已实现：账号/手机号密码登录、短信登录、换设备短信校验、六位安全码、官方人机验证 SDK。
- 已实现：3.7.1、3.7.3、3.7.4、2.8.3 业务协议分支，签名、sealed box、原始 8 字节 nonce AEAD 和响应绑定校验。
- 已实现：取得并加密保存原生业务与 IM 凭据；不保存登录密码、验证码或人机验证结果。
- 已实现：超管权限、CSRF、账号/发起人绑定的 10 分钟事务、账号版本与部署版本校验、当前网站会话复核。
- 已实现：新账号开户专用短信、昵称及密码、协议确认、开户提交前持久屏障、显示账号 ID 后显式登录。
- 已完成离线验证：固定 3.7.4 APK 的签名引导链、原生交换/上下文编码对照及本机加密配置导入。
- 未验收：真实平台是否接受当前请求、官方 SDK 联网流程、真实手机号验证码及设备挑战。
- 接收专用会话恢复、IM 换票和 NIM 长连接见 `docs/native-receiver.md`，真实兼容验收仍未通过。
  已注册不代表已登录，已登录不代表在线收消息。

**用户要求的注册指旺商聊新账号开户，不是网站自助注册，也不是新增账号面板。**
旧适配器 `registration.py` 只有接入事务，不包含开户。2026-10-25 已从用户提供的官网取得
Android 3.7.4 安装包，核实独立开户路由、短信用途、字段及成功后跳转登录行为，
来源、签名、哈希和证据见 [官方客户端核验](official-client-research.md)。
现已替换原 `native_signup_contract_missing` 占位接口，并单独实现 3.7.4 的 Murmur3 摘要、
设备身份、交换版本及注册上下文。官方 ARM64 原生例程的合成样本已与 Go 输出对照，
但尚未通过真实账号与线上响应验收，不把离线一致或注册成功解释为已登录。

## 使用方式

1. 使用带 libsodium 的构建：`go build -tags sodium -o bin/wsl ./cmd/wsl`，执行数据库迁移后重启 API。
2. 网站超管选择旺商聊或 MaiBot 工作台；顶部「机器人连接状态」内的「协议配置」可导入经过核实的协议 JSON。
3. 点击顶部「注册 / 登录」，填写机器人名称，在统一弹窗内选择「原生登录」TAB。
   首次提交有效表单才创建当前工作台的面板；已有机器人从状态表或顶部连接状态打开，不重复创建。
   多账号分别保留各自验证事务，切换查看不提交原生登录。
4. 选择密码或短信方式，人工完成官方人机验证；按平台实际要求补充短信或安全码。
5. 状态为「已登录，会话已加密保存」才表示凭据持久化完成。连接状态仍是「未连接」。
6. 关闭面板只清理表单并停止该面板轮询；「取消验证」会使事务失效。重开可继续同一未过期事务。
7. 「清除会话」擦除本地保存的凭据，但保留原生 UID 与历史关联，防止换号串用历史业务。

注册与登录不再使用两个入口争抢同一账号。同一超管切换 TAB 时，服务端原子替换空闲事务并立即作废旧 ID；
切换不会发短信或提交原生认证，也不重置尝试次数、冷却时间和原验证期限。
正在执行或上游结果未知时禁止直接切换；另一位超管仍不能接管未过期事务。
关闭再打开弹窗可恢复本组件保存的未过期事务和 TAB，但不会保留密码、短信码或手机号输入。
刷新整个页面后，自己的空闲旧流程也能被新流程替换，不再误报为“另一位超管登录”。
开户已经提交但结果待复核的持久化屏障不随切换、关闭或服务重启清除。

### 开户

1. 选择对应工作台，点击顶部「注册 / 登录」，填写机器人名称。打开或切换 TAB 不会创建原生账号或空面板。
2. 切换「新账号注册」TAB；也可从已有空面板的状态行打开。
   已绑定身份、已注册或开户待复核的面板禁用注册 TAB；未导入协议配置时只显示阻塞原因。
3. 填手机号与昵称，确认已阅读旺商聊协议、隐私政策并具有手机号使用权，人工完成人机验证后发注册短信。
4. 输入短信验证码、昵称及 6–16 位混合密码，再次人工验证后提交。
5. 成功后显示的是旺商聊 `accountId`，不是 `native_uid`；点击「登录新账号」显式进入登录。
   登录返回的 accountId 必须与已注册身份一致，才能保存原生 UID 和凭据。

两套工作台的账号池和验证句柄分开。现有面板默认归旺商聊，不自动复制到 MaiBot；
同一原生身份不能绕过全平台唯一绑定而同时登录到两个面板。工作台或账号面板切换不发送登录、断线或配置修改。

开户不会自动调用登录、自动设置安全码、打开消息连接或发群消息。网站账号仍由超管创建。
手机号、密码、短信验证码及人机结果不写入开户记录。昵称采用官方界面 20 个 UTF-16 单元上限，
密码采用官方字符集合与混合规则，并额外拒绝纯空白和控制字符。

不要在聊天、浏览器控制台、截图、版本库或日志里粘贴协议密钥。配置上传使用原始 JSON 字符串，
不在浏览器中把 metadata 的 uint64 解析成 JavaScript 浮点数。

## 部署配置契约

| 字段 | 约束 |
| --- | --- |
| `origin` | 已核验的 HTTPS origin，不能带路径、用户凭据、查询或片段 |
| `headers` | 旧部署所需头部映射；实际只使用小写 `x-version`、`x-device`、`accept`、`content-type`，当前协议覆盖固定版本头 |
| `metadata` | 14 个无符号整数，保留原始整数精度；不要使用浮点序列化工具 |
| `signing_seed` | 标准 Base64，解码后 32 字节 Ed25519 seed |
| `body_key` | 标准 Base64，解码后 32 字节业务请求密钥 |
| `server_key` | 标准 Base64，解码后 32 字节服务端 Curve25519 公钥 |
| `message_key` | 可选，32 字节密钥，登录阶段不使用 |
| `captcha_id` | 原生部署对应的官方人机验证站点 ID |
| `device_id` | 原生部署设备标识，用于获取 IM 凭据 |
| `app_key` | 可选，预留 IM 部署标识；登录阶段不使用 |
| `protocol_version` | `3.7.1`、`3.7.3`、`3.7.4`、`2.8.3`，缺省 `3.7.1` |

配置不能从网站查询接口导出明文，只返回 origin、协议版本、版本号和加密构建可用状态。
配置替换会使已保存会话标记为需要重新登录，并取消内存中的登录事务。
配置与会话分别使用 AES-GCM 及不同 AAD 绑定保存，主密钥仍来自服务端受控环境。
租户数据库角色不能读取部署表及账号凭据列。
出站只访问 HTTPS；拒绝重定向和环境代理；DNS 全部候选地址需通过公网检查，连接实际拨已检查 IP。

### 固定官方客户端的离线配置生成

`tools/native_client_config.py` 只识别已核验的 Android 3.7.4 APK：
先核对完整长度与 SHA-256，再校验内置引导数据的两级 Ed25519 证书、签名和加密内容。
生产 API 必须来自该签名引导，不能把官网、中转页或下载域名当作业务 API。
工具不联网、不安装或初始化客户端；不会调用短信、开户或登录。

```sh
python3 -m venv var/.venv-native-client
var/.venv-native-client/bin/pip install -r tools/requirements-native-client.txt
var/.venv-native-client/bin/python tools/native_client_config.py /private/path/wangwangOnline374.apk \
  --output /private/path/deployment-374.json
```

Python 依赖仅用于离线核验，机器另需 libsodium。输出文件以 `0600`、排他创建，
不会覆盖已有文件或跟随已有符号链接；设备签名 seed 和设备标识每次独立生成，
不应反复生成并替换已使用的身份。标准输出只有脱敏摘要，不输出协议密钥。
上传时选择此文件，不能将内容粘贴到工单、聊天或测试 fixture。

2026-10-25 本机开发环境已通过现有 WebUI 导入，配置版本为 1、协议 3.7.4、
加密库可用。选择的服务地址只验证了 TLS 和根路径可达，不代表任何认证路由验收成功。
该配置没有 IM `app_key`，不会开启长连接；新数据库仍默认无配置。

`tools/android374_oracle.py` 在有界 ARM64 模拟器中执行固定安装包的交换和上下文序列化函数，
只供应内存操作及受控 libsodium 调用，使用合成密钥生成回归样本，不执行 APK 启动流程。
测试向量位于 `internal/nativewire/testdata/android374_exchange.json`。
比较时向原生函数提供与 Go 相同的合法 Zstd raw frame；不声称两种压缩器逐字节相同，
也不以此替代网络、风控或真实验证码验收。

## 接口与状态

接口均位于 `/api/v1`，只允许有效网站超管会话；写入需要 CSRF。

| 接口 | 行为 |
| --- | --- |
| `GET/PUT /native-deployment` | 查询脱敏配置状态 / 使用 `version` 导入配置 |
| `POST /accounts/{id}/native-auth` | 使用账号 `version` 开始，返回 `transaction_id`；同一账号同一发起人复用活跃事务 |
| `GET /accounts/{id}/native-auth/{transaction}` | 查询状态，不返回 JWT、IM token 或密码 |
| `POST /accounts/{id}/native-auth/{transaction}` | 执行异步步骤，`202` 后轮询 |
| `DELETE /accounts/{id}/native-auth/{transaction}` | 取消，不代表撤销已被远端处理的登录 |
| `POST /accounts/{id}/forget-session` | 使用 `version` 清除本地凭据 |
| `POST /native-signup` | 使用空面板的 `account_id`、`version` 开始开户事务 |

步骤 `action`：`password`、`sms_request`、`sms_verify`、`sms_resend`、`security_verify`、`retry_finish`。
开户事务只接受 `signup_sms`、`signup_resend`、`signup_submit`，不能混用登录短信或登录步骤；
每次均需 `agreed=true`。最后一步使用 `nickname`、`password`、六位 `code` 和人工 `captcha`，
手机号绑定首次短信请求，最终提交不能通过改写 `account` 换号。
登录表单的数据只随本次请求提交，不落持久化存储或浏览器 storage。
事务最多 12 次步骤，同一账号 10 分钟最多新建 4 次，全局最多 10 个活跃事务。
短信重发最少 60 秒；验证码验证不受重发冷却阻挡。429 遵守 `Retry-After`，账号请求串行，无自动重试。
所有账号在发送前通过 PostgreSQL 原子持久化分配请求 ID，保留原协议毫秒/纳秒及 nonce 格式，
避免并发账号同毫秒碰撞、进程重启或时钟回退后重用本平台请求编号。配置替换不清零高水位。
数据库不可用时拒绝发送，不回退到随机编号或绕过持久化。

状态包括 `pending`、`working`、`sms_required`、`security_required`、`security_setup_required`、
`connection_pending`、`authenticated`、`failed`、`unknown`、`cancelled`；
开户增加 `signup_sms_required` 和 `registered`，并在 View 中返回 `purpose=signup`。
过期事务不可继续，前端按截止时间显示过期。
网络断开、5xx 或响应无法核验时显示结果未知，不能在同一事务直接重新发送登录/短信。
需先人工核对官方客户端，再取消并重新开始。

账号版本、部署版本、网站会话在最终凭据提交事务内重新校验；原生 UID 全局唯一，
不能用新身份覆盖已有账号 UID。事务仅存内存，API 重启后失效，已提交的加密凭据仍在数据库。
Go 字符串的内存回收不提供完全擦除保证；不要将进程转储当作可公开诊断附件。

### 不可幂等开户与复核

`007_native_signup.sql` 的 `native_signup_attempts` 由平台角色独占访问。
最终开户发送前，在事务内复核网站会话、部署版本、面板版本与未绑定状态，再提交 `submitted` 记录。
数据库不可用或持久化未成功时不发送开户。平台不会持锁等待上游 HTTP。

有效成功回包只记录 `registered` 和账号 ID；明确上游拒绝记录 `rejected`，允许修正。
断网、坏回包、5xx、无法确定的 HTTP 状态及成功后记录失败保留 `submitted`。
同面板 `submitted/registered` 有数据库唯一屏障，取消、过期、重启、改配置都不解除；
未确认开户还会阻止在该面板直接登录。账号列表显示「开户结果待复核」。
已提交后即使浏览器取消，仍尽力记录可信回包，但不偷偷重新发请求。

首期尚无自助解锁未知开户结果的接口。必须由超管使用官方客户端核对真实结果并保留证据，
再通过受控运维复核，不能直接把 `submitted` 改成成功或删除记录来“重试”。

## 验证范围

离线 HTTP 服务只使用合成域名、密钥、验证码与凭据，覆盖四种协议、响应绑定、安全码、JWT 轮换、
IM 凭据及 429 不重试。PostgreSQL 集成测试只重建 `wsl_test`，覆盖权限、加密、重复 UID、
配置变化、账号变化、网站退出和取消。它们不替代真实平台验收。
开户补充覆盖专用短信用途、字段名、人工确认、手机绑定、密码规则、不自动登录、
提交前落盘、已注册身份核对、明确拒绝后修正、未知结果跨重启拦截及取消后保留可信结果。
3.7.4 另覆盖 Murmur3、官方交换/上下文固定样本、注册携带设备上下文但不建立用户会话，
以及旧版本/错误摘要不能解开新绑定响应；旧版固定样本保持不变。

真实验收需要已核验协议配置、受控测试账号及人工验证码。不得将正式账号凭据写进测试 fixture，
也不得因认证通过而自动开启接入、群操作或 AI。
